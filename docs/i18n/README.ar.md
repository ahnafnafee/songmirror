## ✨ المميزات

SongMirror يبقي قوائم التشغيل الخاصة بك متطابقة في كل مكان دون إعادة الإضافة اليدوية أو النسخ واحدة تلو الأخرى أو خدمة سحابية مدفوعة تحتفظ بمكتبتك. إنه متعدد المنصات، ومستضاف ذاتيًا، ومفتوح المصدر.

- 🔁 **النسخ المتطابق الحقيقي، وليس الإلحاق فقط** - الإضافات والإزالة. اختر مصدرًا للحقيقة (Spotify افتراضيًا) وسيتبعه الآخرون.
- ⇆ **المجموعات الموثوقة** — ثق في خدمتين أو أكثر (على سبيل المثال Spotify + Apple Music) بينما تظل كل خدمة أخرى محددة بمثابة مرآة للوجهة فقط.
- ⇄ **مزامنة N-way ثنائية الاتجاه** - تنتشر إضافة أو إزالة أي خدمة متصلة إلى جميع الخدمات الأخرى، بدون صدى، خلف حراس الإزالة.
- ⇉ **مزامنة دمج متعددة المصادر** - قم بجدولة الاتحاد المكرر لقوائم تشغيل المكتبة وعناوين URL لقوائم التشغيل العامة في وجهة واحدة، دون حفظ القوائم العامة أو متابعتها.
- ♥ **المسارات المفضلة والمفضلة** - قم بمزامنة المجموعة المفضلة المضمنة في كل خدمة عبر موفري الموسيقى السبعة، إما في المفضلة الخاصة بالوجهة أو في قائمة تشغيل مسماة جديدة.
- 🎯 **مطابقة دقيقة بواسطة ISRC** — هوية التسجيل الدقيقة حيثما كان ذلك متاحًا، مع تقريبية Unicode-متوافقة مع العنوان/الفنان/المدة الاحتياطية (الاختلافات في اعتمادات الفنان المميز، ولاحقات "- 2015 Remaster"، والنصوص غير اللاتينية، وتحميلات الفيديو فقط - تم التعامل مع كل ذلك).
- 🎛️ **عمليات مزامنة متعددة الأسماء** - قم بإعداد العديد من عمليات المزامنة المستقلة كما تريد، كل منها مع خدماتها وقوائم التشغيل والجدول الزمني وحدود الأمان الخاصة بها.
- ↪️ **عمليات نقل لمرة واحدة** — انسخ أي قائمة تشغيل من خدمة إلى أخرى باستخدام شريط التقدم المباشر؛ قم بإيقاف النسخة مؤقتًا أو استئنافها أو إيقافها في منتصفها وحل المسارات غير المتطابقة يدويًا.
- 🕒 **إلحاق المسارات أو الحفاظ على ترتيب المسار** - تصل النسخ إلى نهاية الوجهة افتراضيًا وبسرعة وإضافية. قم بتشغيل "الاحتفاظ بالترتيب المُضاف مؤخرًا" لإعادة كتابة المسارات بعد أقدم مقطع جديد بحيث يتطابق ترتيب التاريخ المضاف مع المصدر.
- 🔗 **النقل من رابط** - الصق عنوان URL لقائمة التشغيل العامة من أي خدمة متصلة وانسخه مباشرة. لا حاجة لحفظه أو متابعته أولاً.
- 🌐 **قوائم التشغيل التي تمت متابعتها** - يمكنك مزامنة ونقل قوائم التشغيل التي تتابعها ولكن لا تمتلكها، وليس فقط تلك التي أنشأتها.
- 📦 **النسخ الاحتياطية المجدولة للبيانات التعريفية** — يمكنك أرشفة مكتبة قائمة التشغيل الكاملة للحساب وفقًا لجدول زمني خاص بها ضمن بيانات التطبيق المستمرة، مع JSON/XML، وحدود الاحتفاظ، وسجل النجاح/الفشل المرئي. تظل التنزيلات لمرة واحدة والاستيراد Soundiiz JSON متاحة أيضًا.
- 💿 **مرآة التنزيل المحلية** - احتفظ بالصوت دون اتصال، مجلد واحد لكل قائمة تشغيل في تخطيط Jellyfin الخاص بـ `AlbumArtist/Album`، مع أغلفة و`.m3u8` محدث تلقائيًا.
- 🛡️ **ضمانات السلامة** - المحاكاة بشكل افتراضي، الحدود القصوى للإضافة/الإزالة لكل تمريرة، حماية صافي الخسارة، حماية اللقطة الفارغة، الإجهاض دون الكتابة عند انتهاء صلاحية الرموز المميزة.
- 🗃️ **أرشيف الأغاني المتنامي** - يتم تسجيل كل مقطع تمت مشاهدته في قاعدة بيانات SQLite محلية (الاسم، الفنان، الألبوم، ISRC، البيانات الوصفية الأولية، أول/آخر ظهور).
- 🧭 **سجل المطابقة القابل للتحرير** - تصفح، وصحح، واحذف كل مطابقة للمسار المخزن مؤقتًا لكل خدمة من صفحة التعيينات، بما في ذلك نتائج "عدم التطابق" التي قد تظل غير مطابقة إلى الأبد.
- 🐳 **يعمل في أي مكان** — واحد `docker compose up -d` لتطبيق المتصفح، أو CLI عادي + cron / Task Scheduler.

> [!IMPORTANT]
> استضافة ذاتية وخاصة حسب التصميم. لا تترك بيانات الاستماع وبيانات الاعتماد الخاصة بك جهازك أبدًا. لا تحتوي واجهة مستخدم الويب على مصادقة — اربطها بـ LAN ولا تقم بإعادة توجيهها إلى الإنترنت.

## 🚀 بداية سريعة

أسرع طريقة لتشغيلها هي Docker — Compose لسحب الصورة المنشورة، وخدمة واجهة مستخدم الويب، وتشغيل عمليات المزامنة الخاصة بك في الموعد المحدد.

للتثبيت المستمر مع إعادة التشغيل التلقائي:

<div dir="ltr">

```bash
git clone https://github.com/ahnafnafee/songmirror.git
cd songmirror
docker compose up -d
```

</div>

أو جرّب صورة GHCR العامة مباشرةً دون استنساخ المستودع:

<div dir="ltr">

```bash
docker run --rm -d --name songmirror -p 127.0.0.1:8888:8080 ghcr.io/ahnafnafee/songmirror:latest
```

</div>

ثم افتح `http://localhost:8888` وقم بتوصيل خدماتك في المتصفح. لا يحتاج إعداد Compose إلى `.env` للبدء؛ يتم تكوين كل شيء في واجهة المستخدم وحفظه ضمن `./data`.

خيار `docker run` المباشر يمكن التخلص منه: `docker stop songmirror` يزيل الحاوية وتكوينها. استخدم Compose للتثبيت الدائم باستخدام بيانات الاعتماد وذاكرة التخزين المؤقت والتنزيلات المستمرة، أو راجع [دليل صورة الحاوية](../docker-image.md) للحصول على العلامات وتثبيت الملخص.

هل تفضل تشغيله بدون Docker؟

<div dir="ltr">

```bash
uv sync
uv run uvicorn songmirror.web:app --host 0.0.0.0 --port 8080   # then open http://127.0.0.1:8080
```

</div>

> يتطلب [`uv`](https://docs.astral.sh/uv/) (Python 3.13+). للحصول على مرآة التنزيل المحلية، أيضًا `uv tool install spotdl` ولديك `ffmpeg` على PATH.

### لغة التطبيق

SongMirror يدعم اللغات الإنجليزية والعربية والتركية والإسبانية والصينية المبسطة والفرنسية والبرتغالية والألمانية واليابانية والهندية والبنغالية والإندونيسية والكورية والإيطالية والفيتنامية. عند التشغيل لأول مرة، تُفحص تفضيلات لغة المتصفح بالترتيب، بما فيها الاختلافات الإقليمية، وتُستخدم أول لغة مدعومة. إذا لم توجد لغة مدعومة، تُستخدم الإنجليزية. غيّر اللغة من **الإعدادات → عام → اللغة**؛ يُحفظ اختيارك في هذا المتصفح ويظل محفوظًا بعد إعادة التحميل. اختر **تلقائي (المتصفح)** للعودة إلى اتباع تفضيلات المتصفح. تستخدم العربية واجهة من اليمين إلى اليسار. تظل أسماء قوائم التشغيل والفنانين والخدمات وبيانات الاعتماد وسجلات التشخيص بقيمها الأصلية.

## 🐳 قيد التشغيل دائمًا: Docker

تعتبر حاوية Docker هي النشر الموصى به: فهي تخدم واجهة مستخدم الويب، وتدير عمليات المزامنة الخاصة بك وفقًا لجداولها، وتعيد التشغيل مع المضيف. Compose يسحب `ghcr.io/ahnafnafee/songmirror:latest`، ويشغله كـ `songmirror`، ويستمر في كل المصادقة + ذاكرة التخزين المؤقت في `./data`.

<div dir="ltr">

```bash
docker compose up -d             # pull the published image + start in the background
# open http://<host>:8888 and connect your services + create syncs in the browser
docker compose logs -f           # watch it work
```

</div>

للتحديث قم بتشغيل `docker compose up -d --pull always`. لإنشاء الخروج الحالي بدلاً من ذلك، قم بتشغيل `docker compose up -d --build`. راجع [دليل صورة الحاوية](../docker-image.md) للحصول على العلامات وتثبيت الملخص والسحب المباشر والتحقق والتحديثات والتراجع.

ليس هناك حاجة إلى `.env` للبدء — كل شيء تم تكوينه في المتصفح وحفظه تحت `./data`. إعداد مفتاح OAuth ورمز الشريك وAPI جميعها مباشرة على صفحة الحسابات؛ يشرح كل معالج المتطلبات الأساسية الخاصة بالخدمة وURI الدقيق لرد الاتصال. ثم أنشئ عمليات المزامنة الخاصة بك على صفحة المزامنة.

فتح SongMirror من كمبيوتر آخر يعمل على `http://<server>:8888`. يستخدم اتصال Spotify الافتراضي جلسة ويب `sp_dc` ملصوقة، لذلك لا يحتاج إلى تطبيق مطور أو عنوان URL لرد الاتصال. إذا كنت تستخدم عمدًا تطبيق المطور القديم OAuth الاحتياطي خلف Docker أو وكيلًا عكسيًا، فاضبط عنوان URL الأساسي المرئي للمتصفح في `.env`:

<div dir="ltr">

```dotenv
SPOTIFY_AUTH_MODE=oauth
SPOTIFY_CLIENT_ID=your-client-id
SPOTIFY_CLIENT_SECRET=your-client-secret
SONGMIRROR_PUBLIC_URL=https://music.example.com
```

</div>

SongMirror سيتم بعد ذلك الإعلان عن `https://music.example.com/oauth/spotify/callback`; سجل عنوان URI هذا بالضبط في لوحة معلومات التطبيق Spotify وأعد إنشاء الحاوية باستخدام `docker compose up -d --force-recreate`. يتم دعم المسار الأساسي للوكيل العكسي أيضًا (على سبيل المثال، `https://example.com/songmirror`). [Spotify يتطلب HTTPS](https://developer.spotify.com/documentation/web-api/concepts/redirect_uri) لكل عملية إعادة توجيه بدون استرجاع؛ يتم قبول HTTP العادي فقط مع عناوين الاسترجاع الحرفية مثل `127.0.0.1`، وليس LAN IP أو `localhost`.

| | |
| --- | --- |

| ميناء | تم نشر واجهة المستخدم على المضيف 8888 (تعيين `8888:8080` في `docker-compose.yml`؛ قم بتغيير جانب المضيف إذا تعارض). LAN-فقط — لا تقم بإعادة توجيهه إلى الإنترنت؛ واجهة المستخدم ليس لديها مصادقة حتى الآن. |
| الثبات | `./data` يحمل بيانات الاعتماد والرموز المميزة وذاكرة التخزين المؤقت وأرشيف الأغنية ولقطات قائمة التشغيل المجدولة ضمن `playlist_backups/`. قم بعمل نسخة احتياطية منه للاحتفاظ بإعداداتك وأرشيفاتك عبر عمليات إعادة البناء. |
| التنزيلات | اضبط `DOWNLOAD_DIR` (في `.env` أو Shell الخاص بك) على مسار الموسيقى المضيف (على سبيل المثال، `F:\Torrent\Music`)؛ إنشاء رابط - يتم تثبيته على `/music`. من Docker، اضبط `JELLYFIN_URL` إلى `http://host.docker.internal:8096`. |
| الجلسات منتهية الصلاحية | يتم استعادة الجلسات المتجددة عند المرور المجدول أو اليدوي التالي. TIDAL جلسات مشغل الويب يتم تجديدها من رمز التحديث الذي تم التقاطه؛ يجب إعادة لصق الرموز المميزة Qobuz وApple Music عند رفضها. ليس هناك حاجة إلى إعادة التشغيل. |

## ⚙️كيفية العمل

كل تمريرة، لكل اسم قائمة تشغيل محدد موجود في المصدر:

1. قم بالتقاط صورة سريعة لقائمة التشغيل المصدر (المسارات، رموز ISRC، تواريخ الإضافة).
2. قم بتسوية قائمة التشغيل التي تحمل نفس الاسم على كل هدف محدد ومتصل بشكل متزامن من خلال قائمة التشغيل المعتمدة من حساب تلك الخدمة API.
3. يتم حل المسارات المفقودة (الروابط المخزنة مؤقتًا → ISRC → البحث المُسجل) وإلحاقها بالأقدم أولاً؛ تتم إزالة المسارات المنطلقة من المصدر خلف الحراس.
4. اختياريًا، يقوم [spotDL](https://github.com/spotDL/spotify-downloader) بمزامنة مجلد صوتي محلي لكل قائمة تشغيل.

المصدر الافتراضي للحقيقة هو Spotify، ولكن الوضع أحادي الاتجاه لا يعتمد على الموفر - يمكن لأي نظير في قائمة التشغيل المتصلة أن يكون المصدر بدلاً من ذلك.

<a id="matching"></a>

### مطابقة

نفس التسلسل الهرمي الذي تستخدمه أدوات الخدمات المشتركة ([TuneLink](https://tommcfarlin.com/case-study-tunelink-matching-music-ai/)، MusicBrainz): المعرف الدقيق → البحث → النتيجة الغامضة.

1. الرابط المخبأ - بمجرد مطابقة المسار المصدر مع معرف كتالوج الهدف / معرف الفيديو، يتم تخزين هذا الرابط وإعادة استخدامه (محصن ضد انحراف العنوان).
2. ISRC — هوية التسجيل الدقيقة حيث تعرضها الخدمة.
3. تم تسجيل البحث — [RapidFuzz](https://rapidfuzz.com/) `token_set_ratio` + Jaro-Winkler، على كل من العنوان الخام والحروف اللاتينية ([anyascii](https://github.com/anyascii/anyascii)) والفنان، مع مراعاة المدة. يعالج هذا، بدون ترميز ثابت:
   - أرصدة الفنانين المتعددين - تسرد إحدى الخدمات كل ميزة، بينما تسرد أخرى الميزة الأساسية (`Arijit Singh, Ved Sharma, …` ↔ `Arijit Singh`).
   - زخرفة العنوان — `(feat. …)`، `- 2015 Remaster`، `(From "…")`، لاحقات "الفيديو الموسيقي الرسمية" الإضافية.
   - الترجمة الصوتية — السيريلية / البنغالية / اليونانية / العربية (`Камин` ↔ `Kamin`, `নেশার বোঝা` ↔ `Neshar Bojha`).
   - مسارات الفيديو فقط - يعود بحث YouTube إلى مرشح `videos` للمسارات المستقلة/OST التي تظهر على YouTube كتحميلات فقط.

يؤدي مرساة المدة إلى فتح تطابق العنوان الأكثر مرونة، لذلك لا يتم قبول إصدار مختلف (`Runaway - Piano Version`) أو غلاف فنان خاطئ عندما يختلف طوله. يتم الإبلاغ عن المسارات التي لا يوجد بها تطابق موثوق وتخطيها.

<a id="multi-source-merge-sync"></a>

### مزامنة دمج متعددة المصادر

تجمع مهمة دمج المصادر قائمة تشغيل صريحة واحدة أو أكثر في وجهة واحدة مختارة. يمكن أن يأتي كل مصدر من مكتبة حساب متصل أو من عنوان URL للموفر العام الملصق؛ يتم حل الأخير إلى الموفر ومعرف قائمة التشغيل مرة واحدة، لذلك لا تحتاج قائمة التشغيل إلى حفظها أو متابعتها ولا تؤدي عمليات التشغيل المجدولة إلى إعادة تشغيل عنوان URL عشوائي.

- اتحاد عضوية واحد - تتم قراءة جميع المكونات قبل التوفيق بين الوجهة. رموز ISRC المشتركة هي تسجيل واحد؛ بدون ISRC، العنوان الدقيق/المحافظ، الفنان، الإصدار، والمدة يؤدي إلى إزالة التكرارات.
- الترتيب الحتمي - أولوية واصف المصدر أولاً، ثم الترتيب الذي يتم إرجاعه بواسطة كل قائمة تشغيل مصدر. يمتلك التواجد الأول موضع الوجهة ويعرض بيانات التعريف؛ تعمل النسخ اللاحقة فقط على إثراء البيانات التعريفية المفقودة للهوية.
- عمليات الإزالة الآمنة للاتحاد - لا يمكن إزالة مسار الوجهة إلا عندما تجده البطاقة الكاملة غائبة عن كل مصدر مكون. يؤدي المصدر الفاشل أو المقطوع أو المشوه أو غير المتاح أو الفارغ بشكل غير معروف إلى تعطيل كل عملية إزالة لهذا المرور، بينما قد تستمر الإضافات الآمنة من المصادر القابلة للقراءة.
- الإلحاق فقط بشكل افتراضي — اترك إزالة المسارات غير الموجودة من كل مصدر في وضع إيقاف التشغيل للاحتفاظ بجميع المسارات الوجهة فقط. يؤدي تشغيله إلى اختيار غطاء الإزالة العادي لكل تمريرة بعد مرور واقي القراءة الكاملة.

تستهدف وظائف الدمج حاليًا قائمة تشغيل موفر واحد؛ المرآة المنفصلة التي تقودها Spotify التنزيل المحلي/Jellyfin غير متاحة لمهمة مجمعة.

<a id="authoritative-groups"></a>

### المجموعات الرسمية

استخدم مجموعة موثوقة عندما تقوم بتنظيم نفس قائمة التشغيل المنطقية على خدمتين أو أكثر، ولكنك تريد أن تتبعها كل خدمة أخرى محددة. الإعداد النموذجي هو Spotify + Apple Music كمصادر، مع TIDAL، Qobuz، Deezer، Amazon Music، وYouTube Music كمرايا.

- العضوية تأتي فقط من السلطات - المسار المضاف على Spotify أو Apple Music ينتشر إلى السلطة الأخرى وكل مرآة. المسار المضاف فقط على المرآة ينجرف؛ ولا يتم استيراده مرة أخرى إلى السلطات.
- سلطة أمر واحدة - اختر السلطة التي توفر أسماء قوائم التشغيل وترتيب الإضافات. ولا تزال السلطات الأخرى تساهم بتغييرات العضوية.
- تنتشر عمليات الإزالة المؤكدة من أي من المرجعين - يجب أن يظهر الغياب في قراءتين كاملتين متتاليتين قبل أن تتمكن من حذف أي شيء. الإضافة المتزامنة من جانب السلطة تفوز بالإزالة.
- لا تحصل المرايا على تصويت أبدًا - يؤدي حذف المسار من المرآة إلى إصلاح تلك المرآة؛ ولا يحذف المسار من Spotify أو Apple Music.
- التمريرة الأولى الآمنة — كل مجموعة سلطة لها خط الأساس الخاص بها. أول تمريرة ناجحة قد تضيف مسارات مفقودة، ولكنها تحتفظ بجميع عمليات الإزالة حتى تثبت تمريرة لاحقة أن خط الأساس مستقر.
- فشل مغلق - إذا تم قطع اتصال أي سلطة، أو كانت غير قابلة للقراءة، أو لا يمكن فتح/إنشاء قائمة التشغيل الخاصة بها، فسيتم تخطي قائمة التشغيل المنطقية بدلاً من الرجوع بصمت إلى عدد أقل من السلطات.

تظل عمليات الحذف معطلة إلى أن تفعّلها صراحة، وتخضع لحد أقصى. ليرتبط محتوى النسخ بالمجموعة المعتمدة بعد حذف المقاطع الزائدة، فعّل **مزامنة حذف المقاطع** لهذه المهمة، أو اضبط `MAX_REMOVALS` عند التشغيل دون واجهة رسومية.

<a id="bidirectional-n-way-sync"></a>

### مزامنة ثنائية الاتجاه (N-way).

بشكل افتراضي، يكون أحد المزودين هو مصدر الحقيقة، وتتدفق التعديلات في اتجاه واحد. في وضع N-way، يكون كل موفر محدد هو نظير: قم بإضافة أو إزالة مسار على أي مقدم وينتشر التغيير إلى الآخرين.

المزامنة ثنائية الاتجاه مستحيلة بدون حالة، لذلك يتم التقاط العضوية الأساسية لكل قائمة تشغيل منطقية بعد كل تمريرة نظيفة. كل تمريرة تفرق كل مزود مقابل تلك اللقطة، وتوحد التغييرات، وتصالح الجميع مع النتيجة:

- خالية من الصدى - تصبح الإضافة المنشورة جزءًا من اللقطة، لذلك لا ترتد مرة أخرى أبدًا.
- المكاسب الإضافية في الصراع - فقدان أغنية أسوأ من الاحتفاظ بأغنية إضافية.
- حماية انهيار القراءة - إذا قرأ مقدم الخدمة فجأة مسارات أقل بكثير من خط الأساس (فواق عابر API)، فسيتم تخطي هذا التمرير بحيث لا يمكن لقراءة واحدة سيئة أن تؤدي إلى حذف جماعي.
- نفس الضمانات في اتجاه واحد - لكل تمريرة `MAX_ADDS` / `MAX_REMOVALS` الحد الأقصى وحماية صافي الخسارة على كل جانب من جوانب الكتابة.
- **الحذف يتطلب تفعيلًا صريحًا** — القيمة الافتراضية لـ `MAX_REMOVALS` هي 0، لذا فإن المقطع الذي يختفي من إحدى الخدمات، سواء حُذف فيها أو أُزيل بسبب الترخيص، يبقى في الخدمات الأخرى ويُسجَّل الحدث فقط. لنشر الحذف، حدّد سقفًا له أو فعّل **مزامنة حذف المقاطع** في الواجهة.

> دائما المحاكاة أولا. قم بالتشغيل بدون `--execute` (أو استخدم المعاينة في واجهة المستخدم) واقرأ الخطة - فهي تطبع كل إضافة/إزالة مقترحة على كل مزود قبل كتابة أي شيء.

<a id="liked-and-favorite-tracks"></a>

### الأغاني المفضلة والمفضلة

في خطوة قوائم التشغيل الخاصة بالمزامنة، حدد مجموعة الإعجابات المضمنة في الخدمة المصدر. SongMirror ثم يسألك عن المكان الذي يجب أن يذهب إليه في كل وجهة محددة: مباشرةً إلى المجموعة المفضلة/المفضلة الخاصة بتلك الخدمة، أو إلى قائمة تشغيل جديدة يمكنك تعديل اسمها المقترح. التحديد الجديد يحظى بالإعجاب فقط؛ قم بتشغيل أيضًا مزامنة كل قائمة تشغيل عادية أو اختر قوائم تشغيل فردية لتضمين كليهما.

يعمل هذا عبر Spotify الأغاني التي أعجبتني، TIDAL/Qobuz/Deezer المقاطع الصوتية المفضلة، Amazon Music إعجاباتي، Apple Music الأغاني المفضلة، وYouTube Music الموسيقى التي أعجبتني. يتم تطبيق نفس مسارات المصالحة ذات الاتجاه الواحد والمجموعة الموثوقة وN-way وحدود الأمان. كما هو الحال مع قوائم التشغيل العادية، يظل حذف المقاطع معطّلًا افتراضيًا حتى تفعيل **مزامنة حذف المقاطع**.

تتعامل منحة مشغل الويب TIDAL التي تم تسجيل الدخول إليها مع كل من قوائم التشغيل العادية والمسارات المفضلة الأصلية عندما تحمل `r_usr` و`w_usr`. يؤدي التقاط الاستجابة الكاملة لرمز تسجيل الدخول إلى الحصول على SongMirror رمز التحديث بالإضافة إلى Bearer قصير الأمد، بحيث يمكن تجديد الجلسة تلقائيًا.

تستخدم بعض عمليات التكامل هذه واجهات ويب الطرف الأول الخاصة بموفري الخدمة ويمكن أن تتغير دون إشعار؛ يسجل [تقييم الجدوى](../design/2026-09-01-liked-tracks-sync-feasibility.md) API وقيود التوزيع لكل مزود.

## 📦 النسخ الاحتياطية للبيانات الوصفية لقائمة التشغيل

لا تتطلب النسخ الاحتياطية موفرًا ثانيًا أو مهمة مزامنة:

- في الإعدادات ← النسخ الاحتياطية لقائمة التشغيل، استخدم إضافة نسخة احتياطية في الأعلى لإضافة حساب متصل. اختر JSON أو XML، ثم حدد تكرارًا مثل يومي أو أسبوعي. تستخدم الفواصل الزمنية المخصصة رقمًا ووحدة. يوفر الاحتفاظ بالنسخ الاحتياطية إعدادات مسبقة للاحتفاظ، أو عددًا مخصصًا، أو جميع النسخ الاحتياطية.
- النسخ الاحتياطية الافتراضية هي `data/playlist_backups/<account-profile-id>/` (أو `/data/playlist_backups/<account-profile-id>/` في Docker). انقر فوق مجلد النسخ الاحتياطي لمنتقي المجلدات المضمن، أو اختر إدخال المسار يدويًا. لا يزال المجلد المخصص يحصل على مجلد فرعي منفصل لكل حساب. استخدام مجلد النسخ الاحتياطي الافتراضي يستعيد الافتراضي. يؤثر تغيير المواقع على النسخ الاحتياطية المستقبلية؛ الملفات القديمة تبقى في مكانها. ينطبق الاحتفاظ والتنزيل الأحدث على الموقع المحدد. لا تؤدي إزالة الجدول الزمني إلى حذف الملفات المحفوظة أبدًا.
- الإعدادات → التنزيلات و Jellyfin → يستخدم مجلد التنزيل نفس المنتقي المدمج والإدخال اليدوي. اختر مجلدًا يمكن الوصول إليه من مكتبتك Jellyfin. تتبع التنزيلات جدول كل مزامنة تم اختيارها في علامة التبويب "مزامنة". يعرض المنتقي مسارات المضيف التي تم تكوينها (على سبيل المثال، `F:\Torrent\Music`) مع الاحتفاظ بتعيين Docker (`/music`) داخليًا. لم تتغير عمليات تحميل التنزيل الحالية. يجب أولاً مشاركة المجلدات المضيفة الإضافية كـ Docker bind mounts؛ يؤدي اختيار مجلد غير مثبت إلى ظهور خطأ ويترك الإعداد الحالي دون تغيير.

- تعرض بطاقة الإعدادات نفسها عملية التشغيل التالية وعدد اللقطات المخزنة وآخر ملف ناجح وعددها وآخر فشل. النسخ الاحتياطي الآن يصطف في قائمة الانتظار للتشغيل الآمن عند الطلب؛ يقوم تنزيل الأحدث باسترداد أحدث اللقطة المستمرة.
- في صفحة قوائم التشغيل، استخدم التصدير على بطاقة خدمة لتنزيل كل قائمة تشغيل من تلك الخدمة في ملف واحد بإصدار JSON أو XML.
- افتح قائمة تشغيل لتصدير قائمة التشغيل تلك فقط. يتبع خيار Soundiiz [Soundiiz شكل الاستيراد JSON الموثق](https://soundiiz.com/data/fileExamples/playlistExport.json)، لذلك يمكن تحميل قائمة الأغاني التي تم تنزيلها من خلال قائمة تشغيل الاستيراد الخاصة بـ Soundiiz → من تدفق الملف.
- SongMirror JSON/XML يحافظ على ترتيب قائمة التشغيل وأسماءها بالإضافة إلى معرفات المسار/التكرار للموفر، وISRCs المتاحة، والفنانين، والألبومات، ومواضع مسارات الألبوم، والمدد، والتواريخ المضافة، وروابط العمل الفني، وعلامات الإدخال غير المتاحة. تظل أشباح الكتالوج بدون معرف في النسخة الاحتياطية بدلاً من الاختفاء. لا تحتوي الملفات على ملفات تعريف الارتباط أو الرموز المميزة أو رؤوس الطلبات أو المعاينات أو عناوين URL لملفات البث.

يتم تنزيل عمليات التصدير اليدوية بواسطة المتصفح إلى الجهاز الذي يقوم بتشغيل واجهة المستخدم. تستخدم عمليات التصدير المجدولة حجم بيانات التطبيق الحالي، لذلك لا يلزم وجود مسار مضيف ثانٍ أو تحميل حاوية. يقرأ النسخ الاحتياطي قائمة الانتظار خلف عمليات المزامنة والنقل بدلاً من الوصول إلى عملاء الموفر بشكل متزامن. يتيح الحقل `schema_version` للإصدارات المستقبلية تطوير التنسيق غير المفقود دون جعل اللقطات القديمة غامضة.

<a id="built-in-folder-picker"></a>

### منتقي المجلدات المدمج

انقر فوق حقل المجلد أو تصفح... لفتح المنتقي المضمن. استخدم المواقع، ومسارات التنقل القابلة للنقر، والخلف، والأمام، والأعلى في مجلد واحد للتنقل. انقر فوق مجلد لتحديده؛ انقر نقرًا مزدوجًا، ثم اضغط على Enter، أو استخدم السهم الخاص به لفتحه. يقوم البحث بتصفية المجلد الحالي. أدخل مسار المجلد يقبل العنوان الكامل. حدد مجلدًا لتحديث المسودة؛ احفظ الإعدادات أو الجدول الزمني لتطبيقها. إلغاء يترك المسودة دون تغيير. لا يلزم وجود مساعد سطح المكتب أو عملية إضافية.

يقوم المجلد الجديد بإنشاء مجلد فرعي مسمى في الموقع المفتوح حاليًا، ثم يفتحه. لا يتم الكتابة فوق العناصر الموجودة أبدًا. إلغاء إدخال الاسم لا يؤدي إلى أي شيء؛ يؤدي إلغاء المنتقي بعد الإنشاء إلى ترك المجلد الجديد على القرص. لا يتغير موقع النسخ الاحتياطي أو التنزيل المحفوظ إلا بعد التحديد والحفظ. في Docker، يشرح المنتقي المسارات التي تتم مشاركتها ويعرض كلاً من مسار الحاوية ومسار الكمبيوتر الذي تم تكوينه عندما يكون متاحًا.

## 💿 مرآة التنزيل المحلية (Jellyfin)

احتفظ بنسخة صوتية دون اتصال بالإنترنت من كل قائمة تشغيل متزامنة، مجلد واحد لكل قائمة تشغيل، عبر [spotDL](https://github.com/spotDL/spotify-downloader). المزامنة هي انعكاس حقيقي: يتم تنزيل المسارات الجديدة، ويتم حذف المسارات المحذوفة محليًا. التخطيط جاهز Jellyfin — أشر إلى مكتبة الموسيقى Jellyfin في دليل التنزيل وستظهر كل من المقطوعات الموسيقية وقوائم التشغيل، مع البقاء على اطلاع دائم بكل مرور:

<div dir="ltr">

```text
<DOWNLOAD_DIR>/
  <Playlist>/
    <Playlist>.m3u8          # auto-(re)generated; Jellyfin imports it as a playlist
    cover.jpg                # the source playlist cover, highest resolution
    <AlbumArtist>/
      <Album>/
        Artists - Title.mp3  # tagged + cover art embedded
```

</div>

قم بتفعيلها عن طريق ضبط `DOWNLOAD_DIR` وتثبيت spotDL + ffmpeg:

<div dir="ltr">

```bash
uv tool install spotdl       # isolated CLI; or: pipx install spotdl
# ffmpeg required: winget install ffmpeg   (or: spotdl --download-ffmpeg)
```

</div>

- تزايدي — بعد التنزيل الكامل الأول، يتم جلب المسارات المضافة حديثًا فقط؛ يتم تقليم المسارات التي تمت إزالتها (ومجلدات الألبومات الفارغة الخاصة بها). يستمر التشغيل المتقطع في التمريرة التالية.
- الأحدث-الأول `.m3u8` — مكتوب بترتيب التاريخ المضاف، الأحدث في الأعلى (اضبط `LOCAL_MIRROR_ORDER=oldest` للقلب). أعد بناء الأغلفة/العلامات/مرات m من الملفات الموجودة باستخدام `uv run main.py --refresh-local`.
- أغلفة قائمة التشغيل في Jellyfin — Jellyfin تتجاهل ملف الغلاف بجوار m3u، لذا قم بتعيين `JELLYFIN_URL` + `JELLYFIN_API_KEY` وكل تمريرة تقوم بتحميل غلاف قائمة التشغيل الحقيقي عبر Jellyfin API.
- جودة الصوت — المصدر هو YouTube، لذلك بدون ملف تعريف الارتباط Premium لموسيقى YT، يصل السقف إلى 128–160 كيلوبت في الثانية تقريبًا. `LOCAL_MIRROR_FORMAT=opus` يحتفظ بالبث الأصلي لـ YouTube بدون إعادة ترميز mp3؛ ملف تعريف الارتباط Premium (`LOCAL_MIRROR_COOKIE_FILE`) يفتح 256 كيلوبت في الثانية AAC. يغيّر اختيار `flac` حاوية الإخراج، لكنه لا يحوّل مصدرًا مضغوطًا مع فقدان بعض بيانات الصوت إلى صوت مضغوط دون فقدان.

يستخدم مسار FLAC الحالي لـ Monochrome موارد التشغيل ذات الاستخدام الواحد والمرتبطة بالمتصفح بدلاً من تصدير الملفات المستقر والمعتمد من قبل الموفر API، لذا فإن SongMirror لا يقوم بتشغيله تلقائيًا. استخدم المرآة المحلية فقط للمحتوى الذي تملكه أو المصرح لك بنسخه.

## 🔌 ربط كل خدمة

في تطبيق الويب، ترشدك صفحة الحسابات خلال كل خدمة وتعرض القيم الدقيقة المطلوب لصقها. لا شيء يتم بالوكالة من خلال طرف ثالث.

<a id="credential-renewal"></a>

### تجديد الاعتماد

SongMirror يقوم بتحديث بيانات الاعتماد في الوقت المناسب، وليس باستخدام مؤقت تحديث الرمز المميز. يقوم كل تمرير مزامنة يدوي أو مجدول بالتحقق من صحة الموصلات التي يستخدمها ويجدد رموز الوصول المدعومة قبل الطلب الأول (أو مرة واحدة بعد رفض المصادقة). من الطبيعي أن تنتهي صلاحية رمز الوصول قصير الأمد بين التمريرات، ما يهم هو رمز التحديث الدائم أو ملف تعريف الارتباط للتجديد. تتحقق صفحة الحسابات من صحة الحالة عند تحميل التركيز أو استعادته، ولكنها ليست صيانة للجلسة في الخلفية؛ جداول المزامنة الممكنة هي.

| الخدمة | سلوك التجديد |
| --- | --- |
| Spotify | يقوم الاتصال الافتراضي بإنشاء رمز وصول لمشغل الويب من ملف تعريف الارتباط `sp_dc` المحفوظ عند الطلب وإعادة المحاولة باستخدام رمز مميز جديد بعد `401`؛ لا يزال من الممكن إلغاء جلسة تسجيل الدخول الأساسية. يظل تطبيق المطور القديم OAuth مدعومًا لعمليات التثبيت الحالية. |
| TIDAL | يتم تجديد رمز الوصول لمشغل الويب المستورد تلقائيًا من خلال `auth.tidal.com` باستخدام رمز التحديث من استجابة تسجيل الدخول. SongMirror يحتفظ برمز التحديث الحالي عندما تحذفه الاستجابة ويستمر في رمز مميز تم تدويره عندما يقوم TIDAL بإرجاع واحد. لا يزال تسجيل الخروج أو الإلغاء يتطلب التقاطًا جديدًا. |
| Qobuz | يتم استخدام `X-User-Auth-Token` الملصق حتى Qobuz يرفضه، ثم يجب التقاطه مرة أخرى. |
| Deezer | الأنبوب قصير العمر JWT يتجدد تلقائيًا من `refresh-token` المحفوظة قبل الاستخدام ومرة ​​واحدة بعد `401/403`؛ تستمر حالة التجديد المدورة. |
| Amazon Music | يتم تجديد رمز الوصول إلى الويب من خلال `/pandaToken` باستخدام وكيل مستخدم المتصفح والمرجع وملفات تعريف الارتباط المدرجة في القائمة المسموح بها. يعمل تدفق `POST config.json?skipToken=false` الحالي على تمهيد سياق الجهاز عند الحاجة، وتستمر ملفات تعريف الارتباط التي تم تدويرها. لا يزال تسجيل الخروج أو التغييرات الأمنية أو الإلغاء من جانب الخادم يتطلب التقاطًا جديدًا. |
| Apple Music | لا يمكن تجديد Bearer و Media-User-Token الملصقة بواسطة SongMirror ويجب التقاطها مرة أخرى بعد الرفض. |
| YouTube Music | Data API OAuth يتم التحديث تلقائيًا خلال 60 ثانية من انتهاء الصلاحية. يحاول وضع المتصفح تدوير ملف تعريف الارتباط الخاص بـ Google كلما تم إنشاء هدف مزامنة؛ يجب تصدير جلسة المتصفح منتهية الصلاحية مرة أخرى. |
| Jellyfin | لا يحتوي المفتاح API على دورة تحديث لرمز الوصول؛ استبدله فقط في حالة إبطاله أو حذفه. |

<a id="spotify"></a>

### Spotify

1. قم بتسجيل الدخول على <https://open.spotify.com>.
2. افتح المتصفح DevTools (`F12`) → التطبيق (Chrome/Edge) أو التخزين (Firefox) → ملفات تعريف الارتباط → `https://open.spotify.com`.
3. انسخ قيمة ملف تعريف الارتباط `sp_dc` والصقه في الحسابات → Spotify.

تتعامل جلسة الويب الفردية التي تم تسجيل الدخول فيها مع تصفح المكتبة وقراءة قائمة التشغيل وكتابتها والبحث في الكتالوج. لا يتطلب الأمر تطبيق مطور Spotify أو مفتاح API أو حساب Premium. تعامل مع `sp_dc` ككلمة مرور: SongMirror يخزنها في دليل البيانات الخاصة به، لكن التكامل يستخدم عمليات مشغل الويب الداخلية لـ Spotify وقد يحتاج إلى صيانة إذا قام Spotify بتغييرها. تظل بيانات اعتماد تطبيق المطور OAuth بمثابة بديل متوافق.

<a id="tidal"></a>

### TIDAL

1. افتح [مشغل الويب TIDAL](https://listen.tidal.com)، افتح DevTools → الشبكة، وقم بتمكين الاحتفاظ بالسجل.
2. قم بتسجيل الخروج ثم قم بتسجيل الدخول مرة أخرى، ثم قم بتصفية قائمة الشبكات للحصول على `oauth2/token`.
3. قم باختيار الطلب `auth.tidal.com/v1/oauth2/token` الناجح. في الحمولة (Chrome/Edge) أو الطلب (Firefox)، انسخ قيمة النموذج `client_id` في حقل معرّف عميل مشغل الويب SongMirror.
4. افتح علامة التبويب "الاستجابة" للطلب وانسخ JSON الكامل إلى الاستجابة المميزة لمشغل الويب. يجب أن تتضمن كلا من `access_token` و`refresh_token`.
5. الاتصال. SongMirror يمارس على الفور منحة التحديث ويرفض الإبلاغ عن النجاح إذا لم يتمكن معرف العميل من تجديده.

معرف العميل OAuth هو بيانات تعريف الطلب وليس المطالبة الرقمية `cid` داخل رمز الوصول الخاص بـ TIDAL. SongMirror يستخرج فقط رمز الوصول ورمز التحديث ومعرف العميل والنطاقات وانتهاء الصلاحية وبلد الكتالوج؛ يتم تجاهل بيانات الاستجابة غير ذات الصلة. يتم تجديده قبل انتهاء الصلاحية مباشرة ومرة ​​واحدة بعد رفض المصادقة من خلال `https://auth.tidal.com/v1/oauth2/token`، مع الحفاظ على دوران رمز التحديث. يظل لصق رأس الطلب OpenAPI الأقدم متوافقًا، ولكن نظرًا لأنه لا يحتوي على رمز تحديث، فإنه لا يزال بحاجة إلى إعادة لصقه بعد انتهاء الصلاحية. يتم استخدام بيانات تعريف الكتالوج وقوائم التشغيل الخاصة بالمستخدم الذي قام بتسجيل الدخول فقط، وتبقى أصول التشغيل خارج هذا التكامل.

<a id="qobuz"></a>

### Qobuz

قم بتسجيل الدخول على <https://play.qobuz.com>، افتح DevTools → الشبكة، وقم بالتصفية للحصول على `api.json/0.2`. اختر أي طلب يحتوي على `X-App-Id` و`X-User-Auth-Token` — بما في ذلك طلب `album/story` مصادق عليه — ثم انسخ رؤوس الطلب الخاصة به أو انسخها كـ cURL وألصقها في المعالج. SongMirror يحافظ على هاتين القيمتين فقط، ويرسلهما باستخدام نفس التدفق المستند إلى الرأس مثل مشغل الويب، ويتجاهل ملفات تعريف الارتباط وبيانات تعريف المتصفح غير ذات الصلة. لا يلزم الحصول على موافقة تجارية API أو معرف المستخدم؛ تظل بيانات اعتماد الشريك الحالي بمثابة بديل لبيئة متوافقة.

يستخدم المحول نقاط نهاية البحث في الكتالوج وقائمة التشغيل فقط، ولا يطلب عناوين URL للبث أو الملف.

<a id="deezer"></a>

### Deezer

سجل دخولك على <https://www.deezer.com>، وافتح DevTools → الشبكة، وأعد تحميل الصفحة. قم بتصفية `auth.deezer.com/login/renew`، وانسخ رؤوس هذا الطلب (أو انسخه كـ cURL)، والصقه في حقل التجديد. قد يقوم Firefox بدلاً من ذلك بنسخ ملفات تعريف الارتباط الخاصة بالطلب ككتلة عارية مفصولة بفاصلة منقوطة؛ هذا الشكل مقبول أيضًا. SongMirror يحتفظ فقط بملف تعريف الارتباط `refresh-token` المخصص ويستخدمه لتجديد أنبوب Deezer قصير العمر JWT تلقائيًا. يمكنك أيضًا لصق طلب `pipe.deezer.com/api` الحالي باعتباره تمهيدًا فوريًا، ولكنه ليس مطلوبًا عند تكوين التجديد. تستخدم عمليات الإضافة والإزالة في قائمة التشغيل جلسة Pipe المتجددة؛ لا حاجة لملف تعريف الارتباط `arl`. تظل الرموز المميزة للمطور OAuth بمثابة احتياطي بيئة متوافقة.

<a id="amazon-music"></a>

### Amazon Music

لا يلزم الحصول على موافقة المطور للموصل الافتراضي. يستخدم نفس طرق GraphQL وتجديد الرمز المميز مثل مشغل الويب Amazon Music:

1. قم بتسجيل الدخول على <https://music.amazon.com> وافتح DevTools → الشبكة.
2. أعد تحميل الصفحة، ثم قم بتصفية `config.json`، ثم حدد طلب تسجيل الدخول. (`pandaToken` يعمل أيضاً عند ظهوره ولكن ليس مطلوباً.)
3. اختر نسخ رؤوس الطلب أو نسخ كـ cURL، ثم قم بلصقه في حقل التجديد. احتفظ بالعناوين `User-Agent` و`Referer` و`Cookie` الكاملة حتى يتمكن SongMirror من إعادة تشغيل نفس سياق المتصفح.
4. اختياريًا، انسخ الرد الذي تم تسجيل الدخول به `config.json` في حقل التمهيد؛ يمكن لـ SongMirror عادةً جلب سياق الجهاز باستخدام جلسة التجديد.

SongMirror يستمد نفس قيمة التفويض `AmznMusic` محليًا ويحدثها من خلال `music.amazon.com/pandaToken` قبل انتهاء الصلاحية أو مرة واحدة بعد رفض المصادقة. أثناء الاتصال، يستخدم طلب التكوين الحالي على نمط المتصفح عند الحاجة إلى سياق الجهاز، ويتطلب `/pandaToken` لسك رمز وصول، ويرفض الاتصال إذا أبطلت Amazon ملف تعريف الارتباط لتجديد الموسيقى. فهو يخزن فقط وكيل مستخدم المتصفح، واللغة، ومرجع الموسيقى، وقائمة مسموح بها لمصادقة Amazon/ملفات تعريف الارتباط للجلسة، وسياق جهاز عميل الموسيقى المحدود؛ يتم تجاهل التحليلات والتجربة ووحدة تحكم AWS وCSRF وبيانات المتصفح الأخرى غير ذات الصلة. لا تزال ملفات تعريف الارتباط هذه حساسة، لذا احتفظ بـ SongMirror خاصًا على LAN الخاص بك. لا يزال من الممكن أن يتطلب تسجيل الخروج أو تغيير كلمة المرور/الأمان أو الإلغاء من جانب أمازون عملية التقاط جديدة واحدة.

هذه واجهة عميل ويب للطرف الأول غير مدعومة ويمكن لشركة Amazon تغييرها دون إشعار. لا يزال [Amazon Music ويب API](https://developer.amazon.com/docs/music/API_web_overview.html) الموثق عبارة عن نسخة تجريبية مغلقة؛ تظل بيانات اعتماد الشريك المعتمد بمثابة بديل اختياري عند تكوينها من خلال متغيرات البيئة.

<a id="apple-music"></a>

### Apple Music

ليست هناك حاجة إلى حساب Apple Developer — رأسان من `music.apple.com` يكفيان. افتح <https://music.apple.com>، سجل الدخول، افتح DevTools → الشبكة، قم بتشغيل أغنية، قم بالتصفية لـ `amp-api.music.apple.com`، ومن نسخ رؤوس أي طلب:

- `authorization: Bearer eyJ...` → Bearer الرمز المميز (الجزء `eyJ...`، بدون `Bearer `)
- `media-user-token: ...` → رمز المستخدم (القيمة الكاملة)

يتيح لك معالج الاتصال لصق الرؤوس الأولية وتحليل القيم لك. الرموز الأشهر الماضية؛ أعد لصقها في صفحة الحسابات عند انتهاء صلاحيتها.

لا يزال بإمكان معرف Apple بدون اشتراك نشط Apple Music الاتصال في وضع الكتالوج فقط. في هذا الوضع، الصق رابط قائمة التشغيل Apple Music العام في عمليات النقل لنسخه إلى خدمة متصلة أخرى. لا يزال تصفح مكتبة Apple والمزامنة المجدولة واستخدام Apple Music كوجهة نقل يتطلب امتياز CloudLibrary المدفوع؛ يُظهر SongMirror أن هذه العمليات غير متاحة بدلاً من التعامل مع بيانات اعتماد الكتالوج الصالحة على أنها منتهية الصلاحية.

<a id="youtube-music"></a>

### YouTube Music

تحدث إلى المسؤول [YouTube Data API v3](https://developers.google.com/youtube/v3)، الذي يتمتع رمز التحديث OAuth الخاص به بالمتانة والبقاء على قيد الحياة عند إعادة التشغيل.

1. في [Google وحدة التحكم السحابية](https://console.cloud.google.com)، قم بإنشاء مشروع، وتمكين YouTube Data API v3، وإنشاء عميل OAuth من نوع أجهزة التلفاز وأجهزة الإدخال المحدودة.
2. في شاشة الموافقة OAuth، قم بتعيين حالة النشر ← قيد الإنتاج (تركها في "الاختبار" تنتهي صلاحية الرمز المميز بعد 7 أيام).
3. في التطبيق، الصق معرف العميل + السر وأكمل رمز الجهاز الذي يظهر على الشاشة.

> الحصة: Data API تسمح بـ 10000 وحدة/اليوم (تكلفة البحث 100، إضافة/إزالة 50). صيانة الحالة المستقرة رخيصة. يمكن للتراكم الكبير لأول مرة أن يصل إلى الحد الأقصى ويستأنف في اليوم التالي.

## 🖥️ بدون واجهة رسومية CLI

تفضل `.env` + كرون / Task Scheduler؟ نفس المحرك يعمل بدون واجهة رسومية.

<div dir="ltr">

```bash
uv sync
cp .env.example .env            # fill in credentials
uv run main.py                  # dry run — prints every add/remove it *would* do
uv run main.py --execute        # apply for real
```

</div>

أعلام مفيدة:

<div dir="ltr">

```bash
uv run main.py --execute --playlists "Aurora,Chill"   # only these pairs
uv run main.py --execute --loop --interval 15m        # run forever
uv run main.py --execute --max-removals 100           # one-off larger cleanup
uv run main.py --execute --sync-mode group --sync-source spotify \
  --authorities spotify,apple --providers spotify,apple,tidal,ytmusic
```

</div>

مفتاح env vars (راجع `.env.example`): بيانات الاعتماد الخاصة بالمزودين الذين تستخدمهم، `PLAYLISTS`، `SYNC_INTERVAL`، `MAX_ADDS` / `MAX_REMOVALS`، `DOWNLOAD_DIR`، `SYNC_MODE`، `SYNC_SOURCE`، `SYNC_AUTHORITIES`، و `PROVIDERS`.

## 🛡️ ضمانات السلامة

عمليات الإزالة مدمرة، لذا فهي محمية:

- المحاكاة هي الوضع الافتراضي - لا شيء يتغير بدون `--execute` (أو إجراء المزامنة الحقيقية لواجهة المستخدم).
- إذا أعاد المصدر 0 مسارات لقائمة تشغيل، يظهر الهدف على أنه غير فارغ، فسيتم تخطي عمليات الإزالة التي تمر (لا يمكن لفشل عابر API إفراغ قائمة تشغيل).
- **الحذف معطّل افتراضيًا** — يمنع `MAX_REMOVALS=0` كل عملية حذف؛ تُسجَّل ولا تُنفَّذ. لذلك لا يؤدي سحب مقطع لأسباب تتعلق بالترخيص من منصة إلى حذفه من بقية المنصات. فعّل الحذف لكل عملية مزامنة عبر **مزامنة حذف المقاطع** أو اضبط `MAX_REMOVALS`. حتى بعد التفعيل، إذا تجاوز عدد عمليات الحذف المعلقة الحد الأقصى في دورة واحدة، تُتخطّى جميعها وتُسجَّل.
- `MAX_ADDS` يحد من كل كتابة تنتج طابعًا زمنيًا في تمرير المزامنة، بما في ذلك إصلاح التسلسل الزمني. إذا كانت مباراة قديمة تم استعادتها تحتاج إلى إعادة تشغيل أكبر مما يسمح به الحد الأقصى، فإن SongMirror يؤجلها إلى التمريرة التالية بدلاً من جعلها تبدو الأحدث أو التسبب في انفجار مزود عملاق. لا يشتمل النقل لمرة واحدة على تصريح تالٍ، لذلك لا يتم تأجيله أبدًا: فهو ينسخ كل مسار مطلوب، ويلحقه بترتيب المصدر ما لم تقم بتشغيل "الاحتفاظ بالطلب المضاف مؤخرًا" لهذا النقل، الذي ينفق مهما كانت تكاليف الإصلاح.
- يقوم إصلاح التسلسل الزمني بإنشاء نسخة مكررة قبل سحب النسخة الأصلية. في الخدمة التي يأخذ حذفها كل نسخة من الأغنية، يجب أن يكون عدد الحافظة صحيحًا، لذلك Apple Music أعد القراءة حتى تصبح النسخ المرحلية مرئية وترفض سحب أي شيء مقابل قراءة لا تزال تتبع كتاباتها الخاصة. Deezer يتخطى الإصلاح بالكامل ويتم إلحاقه دائمًا: لا يحتوي على إدراج موضعي أيضًا، لذا فإن إعادة تشغيل أمر لا يمكنه التعبير عنه لا يستحق المخاطرة بالوجهة. يظهر نموذج النقل باللون الرمادي ويوضح السبب.
- الحماية من صافي الخسارة - يتم تعليق مسار الجانب المستهدف الذي يشبه مسار المصدر الذي لا يتطابق مع تلك الخدمة، ولا يتم حذفه.
- يؤدي أي فشل في مصادقة الموفر إلى إحباط تصريح الموفر على الفور - ولا يوجد حذف جزئي للرموز المميزة منتهية الصلاحية.
- يجب أن تنتهي مهمة الدمج من قراءة كل مصدر مكون قبل الحذف من وجهتها؛ أي قوى لقطة جزئية/فاشلة للمصدر تنتقل إلى سلوك الإلحاق فقط.

## 🗃️ التخزين المؤقت وأرشيف الأغاني

يتم تخزين كل شيء قابل للحل مؤقتًا بحيث تكون تمريرات الحالة الثابتة شبه فورية: ذاكرات التخزين المؤقت للحل لكل خدمة (ISRC + بحث، بما في ذلك الأخطاء)، وذاكرة تخزين مؤقت لقائمة المسارات ذات مفاتيح `snapshot_id`، وروابط المعرف الدقيق في SQLite، وتخطي اللقطة لكل زوج (`unchanged since last clean sync`).

يقوم كل تمرير أيضًا بأرشفة البيانات الوصفية لكل مسار يراه في `song_cache.db` - ملف SQLite الذي ينمو باستمرار. تبقى المقاطع الصوتية التي تمت إزالتها في الأرشيف بالاسم والفنان والألبوم والمدة ISRC واللقطة الأولية JSON والطوابع الزمنية لأول/آخر ظهور:

<div dir="ltr">

```bash
sqlite3 song_cache.db "SELECT name, artist, album, first_seen FROM songs ORDER BY first_seen DESC LIMIT 20"
```

</div>

<a id="resolve-mappings"></a>

### حل التعيينات

تحتفظ كل خدمة بذاكرة التخزين المؤقت الخاصة بها، مما يؤدي إلى تعيين مفتاح `title|artist` عادي لمعرف الكتالوج الذي تطابقه
تلك الخدمة. يتم إعادة استخدام التطابق إلى الأبد، وكذلك نتيجة "عدم التطابق"، وهو ما يجعل المسار فاشلاً
للمطابقة مرة واحدة، ابق لا مثيل له في كل تمريرة لاحقة.

تعرض صفحة التعيينات في واجهة مستخدم الويب ذاكرات التخزين المؤقت هذه مباشرةً، لكل خدمة:

- ابحث في ذاكرة التخزين المؤقت بأكملها حسب العنوان أو الفنان أو المعرف الذي تم حله
- قم بالتصفية للإدخالات التي تم تعيينها يدويًا (تطابق اخترته في محرر تعارض النقل) أو لعدم وجود إدخالات مطابقة
- قم بتصحيح معرف خاطئ عن طريق لصق رابط المسار الصحيح، أو احذف التعيين حتى تبحث عنه البطاقة التالية مرة أخرى
- قم بمسح كل إدخال "لا يوجد تطابق" للخدمة في إجراء واحد، بحيث تحصل مجموعة من عمليات البحث الفاشلة على محاولة أخرى

عندما يتم حل الخطأ الذي تم حذفه لاحقًا، فإن مجرد إلحاقه سيجعل الأغنية القديمة تظهر الأحدث. لقائمة التشغيل
الوجهات، SongMirror بدلاً من ذلك يعيد تشغيل تلك الأغنية واللاحقة الأحدث الموجودة بالفعل من الأقدم إلى الأحدث، ثم يزيلها
النسخ الأقدم. لا يسمح مقدمو الخدمات للعملاء باستعادة الطوابع الزمنية الأصلية، ولكن هذا يحافظ على الطوابع الزمنية الخاصة بهم
النظام المضافة مؤخرا. تظل المجموعات الأصلية التي تم الإعجاب بها/المفضلة للعضوية فقط ولا يتم إعادة تشغيلها مطلقًا.

يتم رفض التعديلات برسالة واضحة أثناء تشغيل المزامنة، لأن المرور يحتفظ بذاكرة التخزين المؤقت في الذاكرة الخاصة به
المدة بأكملها وسيتم الكتابة فوقها عند الانتهاء.

## 🧱 تخطيط المشروع

إدخال CLI: `uv run main.py` (رقاقة رفيعة) أو `python -m songmirror`. دخول الويب: `songmirror.web:app`.

<div dir="ltr">

```text
songmirror/
  engine/       # provider-agnostic sync core (no web deps): runner, matching, targets/, spotify, downloads, archive
  services/     # stateful services over the engine: accounts/ connectors, syncs, sync_service, transfers, playlists, settings
  web/          # FastAPI app: thin HTTP/SSE over services/ (routers/)
frontend/       # React + Vite SPA (built and served by the API in production)
```

</div>

إضافة خدمة أخرى: فئة فرعية `MirrorTarget`، تنفيذ ~8 طرق، إضافة منشئها إلى `engine/targets`' `_REGISTRY` وفئتها إلى `_CLASSES`، وإضافة المطابقة `Connector` تحت `services/accounts`. جميع عمليات التسويات - الفرق، والطلب، وضمانات السلامة، والتسجيل، وتخطي اللقطة - موروثة.

## 🩺 استكشاف الأخطاء وإصلاحها

- `Missing required environment variable` — املأ `.env` (CLI) أو قم بتوصيل الخدمة في واجهة المستخدم.
- تقارير TIDAL `Expired` — قم بتسجيل الخروج ثم تسجيل الدخول مرة أخرى على `listen.tidal.com`، ثم الصق كلاً من `client_id` من حمولة الطلب `oauth2/token` واستجابتها الكاملة JSON في الحسابات. طلب OpenAPI المنسوخ له فقط Bearer قصير الأجل ولا يمكن تجديده.
- TIDAL التقارير HTTP 429 — هذا حد مؤقت للسعر، وليس تسجيل دخول منتهي الصلاحية. SongMirror يكرّم تأخير إعادة محاولة المزود ويخزن مؤقتًا فحوصات صحة الحساب بدلاً من التحقق بشكل متكرر من API.
- Qobuz أو تقارير Apple `Expired` / `401` / `403` — هذه الجلسات الملصقة ليس لها سر متجدد؛ التقاط طلب تسجيل دخول جديد أو رمز مميز في الحسابات.
- TIDAL يقول أن الرمز المميز يفتقر إلى إمكانية الوصول إلى المسار الذي تم الإعجاب به - التقط استجابة رمزية جديدة لمشغل الويب عند تسجيل الدخول تحمل `r_usr` و`w_usr`.
- فشل تجديد Deezer — التقط طلبًا جديدًا `auth.deezer.com/login/renew` (أو ملف تعريف الارتباط `refresh-token` الخاص به). الأنبوب الحالي Bearer وحده ليس سوى تمهيد مؤقت.
- فشل تجديد Amazon Music — التقط طلبًا جديدًا لتسجيل الدخول `POST /config.json?skipToken=false` مع رؤوسه الكاملة `User-Agent` و`Referer` و`Cookie`. الرد JSON اختياري.
- YouTube Music تنتهي صلاحية وضع المتصفح — قم بتصدير رؤوس طلبات المتصفح الجديدة. للحصول على الإعداد غير المراقب الأكثر متانة، استخدم Data API OAuth مع شاشة الموافقة أثناء الإنتاج.
- انتهت صلاحية تقارير Spotify - قم بتسجيل الدخول مرة أخرى على `open.spotify.com` والصق ملف تعريف الارتباط `sp_dc` الجديد في الحسابات.
- لا تتم مزامنة قائمة التشغيل - تأكد من وجودها في نطاق قائمة التشغيل الخاصة بالمزامنة وأنها موجودة في المصدر (يتم إنشاء الأهداف تلقائيًا بتمريرة حقيقية).
