## ✨ विशेषताएँ

SongMirror आपकी प्लेलिस्ट को मैन्युअल रूप से दोबारा जोड़ने, एक-एक करके कॉपी करने, या आपकी लाइब्रेरी को सशुल्क क्लाउड सेवा के बिना हर जगह समान रखता है। यह क्रॉस-प्लेटफ़ॉर्म, सेल्फ-होस्टेड और ओपन सोर्स है।

- 🔁 **सच्ची प्रतिबिम्बन, केवल परिशिष्ट नहीं** - परिवर्धन और निष्कासन। सत्य का स्रोत चुनें (डिफ़ॉल्ट रूप से Spotify) और अन्य लोग उसका अनुसरण करें।
- ⇆ **आधिकारिक समूह** - दो या दो से अधिक सेवाओं पर भरोसा करें (उदाहरण के लिए Spotify + Apple Music) जबकि प्रत्येक अन्य चयनित सेवा केवल गंतव्य दर्पण बनी रहती है।
- ⇄ **द्विदिशात्मक एन-वे सिंक** - किसी भी कनेक्टेड सेवा पर एक ऐड या रिमूवल अन्य सभी को इको-फ्री, रिमूवल गार्ड के पीछे प्रचारित करता है।
- ⇉ **मल्टी-सोर्स मर्ज सिंक** - सार्वजनिक सूचियों को सहेजे या उनका अनुसरण किए बिना, लाइब्रेरी प्लेलिस्ट और सार्वजनिक प्लेलिस्ट यूआरएल के डुप्लिकेट यूनियन को एक गंतव्य में शेड्यूल करें।
- ♥ **पसंद किए गए और पसंदीदा ट्रैक** - प्रत्येक सेवा के अंतर्निहित पसंदीदा संग्रह को सभी सात संगीत प्रदाताओं में सिंक करें, या तो गंतव्य के अपने पसंदीदा या एक नए नामित प्लेलिस्ट में।
- 🎯 **ISRC द्वारा सटीक मिलान** - जहां उपलब्ध हो वहां सटीक रिकॉर्डिंग पहचान, लगभग Unicode-संगत शीर्षक/कलाकार/अवधि फ़ॉलबैक (फ़ीचर्ड-कलाकार क्रेडिट में अंतर, "- 2015 रेमास्टर" प्रत्यय, गैर-लैटिन स्क्रिप्ट, केवल-वीडियो अपलोड - सभी नियंत्रित)।
- 🎛️ **एकाधिक नामित सिंक** - आप जितने चाहें उतने स्वतंत्र सिंक सेट करें, प्रत्येक की अपनी सेवाओं, प्लेलिस्ट, शेड्यूल और सुरक्षा कैप के साथ।
- ↪️ **एकमुश्त स्थानांतरण** - लाइव प्रोग्रेस बार के साथ किसी भी प्लेलिस्ट को एक सेवा से दूसरी सेवा में कॉपी करें; रोकें, फिर से शुरू करें, या कॉपी के बीच में रोकें, और बेजोड़ ट्रैक को मैन्युअल रूप से हल करें।
- 🕒 **ट्रैक जोड़ें या ट्रैक ऑर्डर संरक्षित करें** - डिफ़ॉल्ट, तेज़ और एडिटिव द्वारा प्रतियां गंतव्य के अंत में उतरती हैं। सबसे पुराने नए के बाद ट्रैक को फिर से लिखने के लिए हाल ही में जोड़े गए ऑर्डर को संरक्षित करें पर स्विच करें ताकि दिनांक-जोड़ा गया ऑर्डर स्रोत से मेल खाए।
- 🔗 **एक लिंक से स्थानांतरण** - किसी भी कनेक्टेड सेवा से एक सार्वजनिक प्लेलिस्ट यूआरएल पेस्ट करें और इसे सीधे कॉपी करें। इसे पहले सहेजने या अनुसरण करने की आवश्यकता नहीं है.
- 🌐 **फ़ॉलो की गई प्लेलिस्ट** - आपके द्वारा फ़ॉलो की गई प्लेलिस्ट को सिंक और ट्रांसफ़र करें लेकिन आपके पास नहीं हैं, न कि केवल आपके द्वारा बनाई गई प्लेलिस्ट।
- 📦 **शेड्यूल किए गए मेटाडेटा बैकअप** - JSON/XML, अवधारण सीमा और दृश्यमान सफलता/असफलता इतिहास के साथ, लगातार ऐप डेटा के तहत किसी खाते की संपूर्ण प्लेलिस्ट लाइब्रेरी को अपने शेड्यूल पर संग्रहित करें। एक बार डाउनलोड और आयात के लिए तैयार Soundiiz JSON भी उपलब्ध रहते हैं।
- 💿 **स्थानीय डाउनलोड मिरर** - ऑफ़लाइन ऑडियो, Jellyfin के `AlbumArtist/Album` लेआउट में प्रति प्लेलिस्ट एक फ़ोल्डर, कवर और एक ऑटो-अपडेटेड `.m3u8` के साथ रखें।
- 🛡️ **सुरक्षा सुरक्षा उपाय** - डिफ़ॉल्ट रूप से सिमुलेशन, प्रति-पास ऐड/रिमूवल कैप, नेट-लॉस सुरक्षा, खाली-स्नैपशॉट गार्ड, टोकन समाप्त होने पर बिना लिखे ही बंद हो जाता है।
- 🗃️ **लगातार बढ़ता हुआ गीत संग्रह** - अब तक देखा गया प्रत्येक ट्रैक स्थानीय SQLite डेटाबेस (नाम, कलाकार, एल्बम, ISRC, कच्चा मेटाडेटा, पहली/आखिरी बार देखा गया) में रिकॉर्ड किया गया है।
- 🧭 **संपादन योग्य मिलान इतिहास** - मैपिंग पृष्ठ से प्रति सेवा प्रत्येक कैश्ड ट्रैक मैच को ब्राउज़ करें, सही करें और हटाएं, जिसमें "कोई मिलान नहीं" परिणाम भी शामिल हैं जो अन्यथा हमेशा के लिए बेजोड़ रहेंगे।
- 🐳 **कहीं भी चलता है** - ब्राउज़र ऐप के लिए एक `docker compose up -d`, या सादा सीएलआई + क्रॉन / Task Scheduler।

> [!IMPORTANT]
> डिज़ाइन द्वारा स्व-होस्टेड और निजी। आपका सुनने का डेटा और क्रेडेंशियल आपकी मशीन को कभी नहीं छोड़ते। वेब यूआई का कोई प्रमाणीकरण नहीं है - इसे अपने LAN से बांधें और इसे इंटरनेट पर पोर्ट-फ़ॉरवर्ड न करें।

## 🚀 त्वरित शुरुआत

इसे चलाने का सबसे तेज़ तरीका Docker है - Compose प्रकाशित छवि खींचता है, वेब यूआई परोसता है, और आपके सिंक को शेड्यूल पर चलाता है।

स्वचालित पुनरारंभ के साथ सतत स्थापना के लिए:

```bash
git clone https://github.com/ahnafnafee/songmirror.git
cd songmirror
docker compose up -d
```

या रिपॉजिटरी को क्लोन किए बिना सीधे सार्वजनिक GHCR छवि आज़माएँ:

```bash
docker run --rm -d --name songmirror -p 127.0.0.1:8888:8080 ghcr.io/ahnafnafee/songmirror:latest
```

फिर `http://localhost:8888` खोलें और अपनी सेवाओं को ब्राउज़र में कनेक्ट करें। Compose सेटअप को प्रारंभ करने के लिए `.env` की आवश्यकता नहीं है; सब कुछ यूआई में कॉन्फ़िगर किया गया है और `./data` के तहत सहेजा गया है।

प्रत्यक्ष `docker run` विकल्प डिस्पोजेबल है: `docker stop songmirror` कंटेनर और उसके कॉन्फ़िगरेशन को हटा देता है। लगातार क्रेडेंशियल, कैश और डाउनलोड के साथ टिकाऊ इंस्टॉलेशन के लिए Compose का उपयोग करें, या टैग और डाइजेस्ट पिनिंग के लिए [कंटेनर छवि गाइड](../docker-image.md) देखें।

इसे Docker के बिना चलाना पसंद करेंगे?

```bash
uv sync
uv run uvicorn songmirror.web:app --host 0.0.0.0 --port 8080   # then open http://127.0.0.1:8080
```

> [`uv`](https://docs.astral.sh/uv/) (Python 3.13+) की आवश्यकता है। स्थानीय डाउनलोड मिरर के लिए, `uv tool install spotdl` भी रखें और PATH पर `ffmpeg` भी रखें।

### ऐप भाषा

SongMirror अंग्रेजी, अरबी, तुर्की, स्पेनिश, सरलीकृत चीनी, फ्रेंच, पुर्तगाली, जर्मन, जापानी, हिंदी, बंगाली, इंडोनेशियाई, कोरियाई, इतालवी और वियतनामी का समर्थन करता है। पहली बार खुलने पर ब्राउज़र की भाषा प्राथमिकताएँ क्रम से जाँची जाती हैं, जिनमें क्षेत्रीय रूप भी शामिल हैं, और पहली समर्थित भाषा चुनी जाती है। कोई भाषा समर्थित न होने पर अंग्रेज़ी इस्तेमाल होती है। **सेटिंग्स → सामान्य → भाषा** में भाषा बदलें। चुनाव इसी ब्राउज़र में सहेजा जाता है और पेज दोबारा लोड करने पर भी बना रहता है। ब्राउज़र की प्राथमिकताएँ फिर से अपनाने के लिए **स्वचालित (ब्राउज़र)** चुनें। अरबी इंटरफ़ेस दाएँ से बाएँ दिखाई देता है। प्लेलिस्ट, कलाकार और सेवा के नाम, क्रेडेंशियल तथा निदान लॉग अपने मूल रूप में रहते हैं।

## 🐳 हमेशा चालू: Docker

Docker कंटेनर अनुशंसित परिनियोजन है: यह वेब यूआई की सेवा करता है, आपके सिंक को उनके शेड्यूल पर चलाता है, और होस्ट के साथ पुनः आरंभ करता है। Compose `ghcr.io/ahnafnafee/songmirror:latest` को खींचता है, इसे `songmirror` के रूप में चलाता है, और `./data` में सभी ऑथ + कैश को बनाए रखता है।

```bash
docker compose up -d             # pull the published image + start in the background
# open http://<host>:8888 and connect your services + create syncs in the browser
docker compose logs -f           # watch it work
```

अपडेट करने के लिए `docker compose up -d --pull always` चलाएँ। इसके बजाय वर्तमान चेकआउट बनाने के लिए, `docker compose up -d --build` चलाएँ। टैग, डाइजेस्ट पिनिंग, डायरेक्ट पुल, सत्यापन, अपडेट और रोलबैक के लिए [कंटेनर छवि गाइड](../docker-image.md) देखें।

प्रारंभ करने के लिए किसी `.env` की आवश्यकता नहीं है - सब कुछ ब्राउज़र में कॉन्फ़िगर किया गया है और `./data` के अंतर्गत सहेजा गया है। OAuth, पार्टनर-टोकन, और API-कुंजी सेटअप सभी अकाउंट पेज पर लाइव हैं; प्रत्येक विज़ार्ड सेवा-विशिष्ट आवश्यकताएँ और सटीक कॉलबैक यूआरआई बताता है। फिर सिंक पेज पर अपने सिंक बनाएं।

दूसरे कंप्यूटर से SongMirror खोलने पर `http://<server>:8888` पर काम होता है। डिफ़ॉल्ट Spotify कनेक्शन एक चिपकाए गए `sp_dc` वेब सत्र का उपयोग करता है, इसलिए इसे किसी डेवलपर ऐप या कॉलबैक यूआरएल की आवश्यकता नहीं है। यदि आप जानबूझकर लीगेसी डेवलपर-ऐप OAuth फ़ॉलबैक Docker या रिवर्स प्रॉक्सी का उपयोग करते हैं, तो ब्राउज़र-दृश्यमान आधार URL को `.env` में सेट करें:

```dotenv
SPOTIFY_AUTH_MODE=oauth
SPOTIFY_CLIENT_ID=your-client-id
SPOTIFY_CLIENT_SECRET=your-client-secret
SONGMIRROR_PUBLIC_URL=https://music.example.com
```

SongMirror फिर विज्ञापन देगा `https://music.example.com/oauth/spotify/callback`; उस सटीक यूआरआई को Spotify ऐप डैशबोर्ड में पंजीकृत करें और `docker compose up -d --force-recreate` के साथ कंटेनर को फिर से बनाएं। एक रिवर्स-प्रॉक्सी बेस पथ भी समर्थित है (उदाहरण के लिए, `https://example.com/songmirror`)। प्रत्येक गैर-लूपबैक रीडायरेक्ट के लिए [Spotify की आवश्यकता है HTTPS](https://developer.spotify.com/documentation/web-api/concepts/redirect_uri); सादा HTTP केवल शाब्दिक लूपबैक पते जैसे `127.0.0.1` के साथ स्वीकार किया जाता है, LAN आईपी या `localhost` नहीं।

## ⚙️ यह कैसे काम करता है

स्रोत पर मौजूद प्रत्येक चयनित प्लेलिस्ट नाम के लिए प्रत्येक पास:

1. स्रोत प्लेलिस्ट (ट्रैक, आईएसआरसी, जोड़ी गई तारीखें) का स्नैपशॉट लें।
2. उस सेवा के खाता-अधिकृत प्लेलिस्ट API के माध्यम से समवर्ती रूप से प्रत्येक चयनित, कनेक्टेड लक्ष्य पर समान नाम वाली प्लेलिस्ट का मिलान करें।
3. गुम हुए ट्रैक का समाधान कर दिया गया है (कैश्ड लिंक → ISRC → स्कोर की गई खोज) और सबसे पुराना-पहले जोड़ दिया गया है; स्रोत से गए ट्रैक गार्ड के पीछे हटा दिए जाते हैं।
4. वैकल्पिक रूप से, [spotDL](https://github.com/spotDL/spotify-downloader) प्रति प्लेलिस्ट एक स्थानीय ऑडियो फ़ोल्डर को सिंक करता है।

सत्य का डिफ़ॉल्ट स्रोत Spotify है, लेकिन वन-वे मोड प्रदाता-अज्ञेयवादी है - कोई भी कनेक्टेड प्लेलिस्ट सहकर्मी इसके बजाय स्रोत हो सकता है।

<a id="matching"></a>

### मिलान

क्रॉस-सर्विस टूल द्वारा उपयोग किए जाने वाले समान पदानुक्रम ([TuneLink](https://tommcfarlin.com/case-study-tunelink-matching-music-ai/), MusicBrainz): सटीक पहचानकर्ता → खोज → फ़ज़ी स्कोर।

1. कैश्ड लिंक - एक बार जब स्रोत ट्रैक का लक्ष्य की कैटलॉग आईडी / वीडियो आईडी से मिलान हो जाता है, तो वह लिंक संग्रहीत और पुन: उपयोग किया जाता है (शीर्षक बहाव के लिए प्रतिरक्षा)।
2. ISRC — सटीक रिकॉर्डिंग पहचान जहां सेवा इसे उजागर करती है।
3. स्कोर की गई खोज - [RapidFuzz](https://rapidfuzz.com/) `token_set_ratio` + Jaro-Winkler, कच्चे और रोमानीकृत ([anyascii](https://github.com/anyascii/anyascii)) शीर्षक और कलाकार दोनों पर, अवधि के अनुसार तय की गई। यह हार्डकोडिंग के बिना संभालता है:
   - बहु-कलाकार क्रेडिट - एक सेवा प्रत्येक सुविधा को सूचीबद्ध करती है, दूसरी प्राथमिक (`Arijit Singh, Ved Sharma, …` ↔ `Arijit Singh`) सूचीबद्ध करती है।
   - शीर्षक सजावट - `(feat. …)`, `- 2015 Remaster`, `(From "…")`, अतिरिक्त "आधिकारिक संगीत वीडियो" प्रत्यय।
   - लिप्यंतरण - सिरिलिक / बंगाली / ग्रीक / अरबी (`Камин` ↔ `Kamin`, `নেশার বোঝা` ↔ `Neshar Bojha`)।
   - केवल-वीडियो ट्रैक - YouTube खोज इंडी/ओएसटी ट्रैक के लिए `videos` फ़िल्टर पर वापस आती है जो केवल अपलोड के रूप में YT पर रहते हैं।

अवधि एंकर ढीले शीर्षक मैच को अनलॉक करता है, इसलिए एक अलग संस्करण (`Runaway - Piano Version`) या गलत-कलाकार कवर स्वीकार नहीं किया जाता है जब इसकी लंबाई असहमत होती है। बिना किसी भरोसेमंद मैच वाले ट्रैक की रिपोर्ट की जाती है और उन्हें छोड़ दिया जाता है।

<a id="multi-source-merge-sync"></a>

### मल्टी-सोर्स मर्ज सिंक

मर्ज सोर्स जॉब एक या अधिक स्पष्ट प्लेलिस्ट को एक चुने हुए गंतव्य में जोड़ती है। प्रत्येक स्रोत किसी कनेक्टेड खाते की लाइब्रेरी या चिपकाए गए सार्वजनिक प्रदाता यूआरएल से आ सकता है; उत्तरार्द्ध को एक प्रदाता और प्लेलिस्ट आईडी के लिए एक बार हल किया जाता है, इसलिए प्लेलिस्ट को सहेजने या अनुसरण करने की आवश्यकता नहीं होती है और शेड्यूल किए गए रन एक मनमाना यूआरएल को दोबारा नहीं चलाते हैं।

- एक सदस्यता संघ - गंतव्य के समाधान से पहले सभी घटकों को पढ़ा जाता है। साझा आईएसआरसी एक रिकॉर्डिंग है; बिना ISRC, सटीक/रूढ़िवादी शीर्षक, कलाकार, संस्करण और अवधि साक्ष्य के ओवरलैप ओवरलैप हो जाता है।
- नियतात्मक क्रम - पहले स्रोत विवरणक प्राथमिकता, फिर प्रत्येक स्रोत प्लेलिस्ट द्वारा लौटाया गया क्रम। पहली घटना गंतव्य स्थिति और प्रदर्शन मेटाडेटा का स्वामी है; बाद की प्रतियां केवल लुप्त पहचान मेटाडेटा को समृद्ध करती हैं।
- संघ-सुरक्षित निष्कासन - एक गंतव्य ट्रैक को केवल तभी हटाया जा सकता है जब एक पूर्ण पास इसे प्रत्येक घटक स्रोत से अनुपस्थित पाता है। एक विफल, छोटा, विकृत, अनुपलब्ध, या अनजाने में खाली स्रोत उस पास के लिए हर निष्कासन को अक्षम कर देता है, जबकि पठनीय स्रोतों से सुरक्षित परिवर्धन जारी रह सकता है।
- डिफ़ॉल्ट रूप से केवल-जोड़ें - सभी गंतव्य-केवल ट्रैक रखने के लिए प्रत्येक स्रोत से अनुपस्थित ट्रैक हटाएँ को बंद छोड़ दें। पूर्ण-पढ़े गए गार्ड के गुजरने के बाद इसे चालू करने से यह सामान्य प्रति-पास निष्कासन कैप में बदल जाता है।

मर्ज नौकरियां वर्तमान में एक प्रदाता प्लेलिस्ट को लक्षित करती हैं; समग्र कार्य के लिए अलग Spotify-आधारित स्थानीय डाउनलोड/Jellyfin दर्पण उपलब्ध नहीं है।

<a id="authoritative-groups"></a>

### आधिकारिक समूह

जब आप दो या दो से अधिक सेवाओं पर एक ही तार्किक प्लेलिस्ट को सक्रिय रूप से क्यूरेट करते हैं, लेकिन चाहते हैं कि हर अन्य चयनित सेवा उनका अनुसरण करे तो एक आधिकारिक समूह का उपयोग करें। एक विशिष्ट सेटअप अधिकारियों के रूप में Spotify + Apple Music है, दर्पण के रूप में TIDAL, Qobuz, Deezer, Amazon Music, और YouTube Music है।

- सदस्यता केवल प्राधिकारियों से आती है - Spotify या Apple Music पर जोड़ा गया एक ट्रैक अन्य प्राधिकारी और प्रत्येक दर्पण तक प्रसारित होता है। केवल दर्पण पर जोड़ा गया ट्रैक बहाव है; इसे कभी भी अधिकारियों में वापस आयात नहीं किया जाता है।
- एक आदेश प्राधिकारी - चुनें कि कौन सा प्राधिकारी प्लेलिस्ट नाम और परिवर्धन का क्रम प्रदान करता है। अन्य प्राधिकरण अभी भी सदस्यता परिवर्तन में योगदान करते हैं।
- पुष्टि किए गए निष्कासन किसी भी प्राधिकरण से प्रचारित होते हैं - कुछ भी हटाने से पहले एक अनुपस्थिति लगातार दो पूर्ण पढ़ने में दिखाई देनी चाहिए। एक साथ प्राधिकरण-पक्ष का जोड़ निष्कासन पर जीत हासिल करता है।
- दर्पणों को कभी वोट नहीं मिलता - दर्पण से एक ट्रैक हटाने से वह दर्पण ठीक हो जाता है; यह Spotify या Apple Music से ट्रैक को नहीं हटाता है।
- सुरक्षित पहला पास - प्रत्येक प्राधिकरण सेट की अपनी आधार रेखा होती है। इसका पहला सफल पास लापता ट्रैक को जोड़ सकता है, लेकिन सभी निष्कासन को तब तक रोक कर रखता है जब तक कि बाद का पास यह साबित न कर दे कि बेसलाइन स्थिर है।
- विफल बंद - यदि कोई प्राधिकरण डिस्कनेक्ट हो गया है, अपठनीय है, या उसकी प्लेलिस्ट खोली/बनाई नहीं जा सकती है, तो उस तार्किक प्लेलिस्ट को चुपचाप कम अधिकारियों के पास वापस जाने के बजाय छोड़ दिया जाता है।

गाने हटाने की सुविधा स्पष्ट रूप से चालू करनी होती है और उस पर संख्या की सीमा लागू रहती है। मिरर से अतिरिक्त गाने हटाकर उन्हें प्रामाणिक स्रोतों के गानों से मिलाने के लिए इस कार्य में **गानों का हटना सिंक करें** चालू करें, या ग्राफ़िकल इंटरफ़ेस के बिना चलाते समय `MAX_REMOVALS` सेट करें।

<a id="bidirectional-n-way-sync"></a>

### द्विदिश (एन-वे) सिंक

डिफ़ॉल्ट रूप से एक प्रदाता सत्य का स्रोत होता है और संपादन एक तरह से प्रवाहित होता है। एन-वे मोड में प्रत्येक चयनित प्रदाता एक सहकर्मी है: किसी एक पर ट्रैक जोड़ें या हटाएं और परिवर्तन दूसरों तक फैल जाता है।

द्विदिशीय सिंक स्टेटलेस रूप से असंभव है, इसलिए प्रत्येक तार्किक प्लेलिस्ट की कैनोनिकल सदस्यता को प्रत्येक क्लीन पास के बाद स्नैपशॉट किया जाता है। प्रत्येक पास प्रत्येक प्रदाता को उस स्नैपशॉट से भिन्न करता है, परिवर्तनों को जोड़ता है, और सभी को परिणाम से मेल कराता है:

- इको-मुक्त - एक प्रचारित ऐड स्नैपशॉट का हिस्सा बन जाता है, इसलिए यह कभी भी वापस नहीं आता है।
- संघर्ष पर अतिरिक्त लाभ - एक गीत खोना एक अतिरिक्त गीत रखने से भी बदतर है।
- रीड-कोलैप्स गार्ड - यदि कोई प्रदाता अचानक बेसलाइन (एक क्षणिक API हिचकी) से बहुत कम ट्रैक पढ़ता है, तो उसे पास छोड़ दिया जाता है ताकि एक खराब रीड बड़े पैमाने पर डिलीट न कर सके।
- वन-वे के समान सुरक्षा उपाय - प्रत्येक लेखन पक्ष पर प्रति-पास `MAX_ADDS` / `MAX_REMOVALS` कैप और नेट-लॉस सुरक्षा।
- **गाने हटाने के लिए स्पष्ट अनुमति आवश्यक है** — `MAX_REMOVALS` का डिफ़ॉल्ट मान 0 है। किसी सेवा से गाना हट जाने पर, चाहे वहाँ उसे मिटाया गया हो या लाइसेंस के कारण हटा दिया गया हो, वह दूसरी सेवाओं में बना रहता है और बदलाव केवल लॉग होता है। हटाने का बदलाव दूसरी सेवाओं तक पहुँचाने के लिए सीमा तय करें या इंटरफ़ेस में **गानों का हटना सिंक करें** चालू करें।

> हमेशा पहले अनुकरण करें. `--execute` के बिना चलाएं (या यूआई में पूर्वावलोकन का उपयोग करें) और योजना पढ़ें - यह कुछ भी लिखने से पहले प्रत्येक प्रदाता पर प्रत्येक प्रस्तावित ऐड/रिमूव को प्रिंट करता है।

<a id="liked-and-favorite-tracks"></a>

### पसंदीदा और पसंदीदा ट्रैक

सिंक के प्लेलिस्ट चरण पर, स्रोत सेवा के अंतर्निहित पसंदीदा संग्रह का चयन करें। SongMirror फिर पूछता है कि इसे प्रत्येक चयनित गंतव्य पर कहां जाना चाहिए: सीधे उस सेवा के पसंदीदा/पसंदीदा संग्रह में, या एक नई प्लेलिस्ट में जिसका सुझाया गया नाम आप संपादित कर सकते हैं। नया चयन केवल पसंद किया जाता है; प्रत्येक नियमित प्लेलिस्ट को भी सिंक करें या दोनों को शामिल करने के लिए अलग-अलग प्लेलिस्ट चुनें।

यह Spotify पसंदीदा गाने, TIDAL/Qobuz/Deezer पसंदीदा ट्रैक, Amazon Music मेरी पसंद, Apple Music पसंदीदा गाने, और YouTube Music पर काम करता है। संगीत पसंद आया. वही एक-तरफ़ा, आधिकारिक-समूह, और एन-वे समाधान पथ और सुरक्षा सीमाएँ लागू होती हैं। सामान्य प्लेलिस्ट की तरह, **गानों का हटना सिंक करें** चालू होने तक गाने हटाना डिफ़ॉल्ट रूप से बंद रहता है।

TIDAL का साइन-इन वेब-प्लेयर अनुदान सामान्य प्लेलिस्ट और देशी पसंदीदा ट्रैक दोनों को संभालता है जब इसमें `r_usr` और `w_usr` होता है। संपूर्ण साइन-इन टोकन प्रतिक्रिया कैप्चर करने से SongMirror ताज़ा टोकन के साथ-साथ अल्पकालिक Bearer मिलता है, इसलिए सत्र स्वचालित रूप से नवीनीकृत हो सकता है।

इनमें से कुछ एकीकरण प्रदाताओं के प्रथम-पक्ष वेब इंटरफेस का उपयोग करते हैं और बिना किसी सूचना के बदल सकते हैं; [व्यवहार्यता मूल्यांकन](../design/2026-09-01-liked-tracks-sync-feasibility.md) प्रत्येक प्रदाता के लिए API और वितरण बाधाओं को रिकॉर्ड करता है।

<a id="playlist-metadata-backups"></a>

## 📦 प्लेलिस्ट मेटाडेटा बैकअप

बैकअप के लिए दूसरे प्रदाता या सिंक कार्य की आवश्यकता नहीं होती है:

- सेटिंग्स → प्लेलिस्ट बैकअप पर, कनेक्टेड अकाउंट जोड़ने के लिए शीर्ष पर बैकअप जोड़ें का उपयोग करें। JSON या XML चुनें, फिर दैनिक या साप्ताहिक जैसी आवृत्ति चुनें। कस्टम अंतराल एक संख्या और एक इकाई का उपयोग करते हैं। बैकअप रखें, रिटेंशन प्रीसेट, एक कस्टम गिनती या सभी बैकअप प्रदान करता है।
- बैकअप डिफ़ॉल्ट रूप से `data/playlist_backups/<account-profile-id>/` (या `/data/playlist_backups/<account-profile-id>/` में Docker) होता है। अंतर्निहित फ़ोल्डर पिकर के लिए बैकअप फ़ोल्डर पर क्लिक करें, या मैन्युअल रूप से पथ दर्ज करें चुनें। एक कस्टम फ़ोल्डर को अभी भी प्रत्येक खाते के लिए एक अलग सबफ़ोल्डर मिलता है। डिफ़ॉल्ट बैकअप फ़ोल्डर का उपयोग डिफ़ॉल्ट को पुनर्स्थापित करता है। स्थान बदलने से भविष्य के बैकअप प्रभावित होते हैं; पुरानी फ़ाइलें जहाँ थीं वहीं पड़ी रहती हैं। प्रतिधारण और नवीनतम डाउनलोड चयनित स्थान पर लागू होते हैं। शेड्यूल हटाने से सहेजी गई फ़ाइलें कभी नहीं हटतीं।
- सेटिंग्स → डाउनलोड और Jellyfin → डाउनलोड फ़ोल्डर समान अंतर्निहित पिकर और मैन्युअल प्रविष्टि का उपयोग करता है। अपनी Jellyfin लाइब्रेरी के लिए पहुंच योग्य फ़ोल्डर चुनें। डाउनलोड सिंक टैब पर प्रत्येक ऑप्ट-इन सिंक शेड्यूल का पालन करते हैं। पिकर आंतरिक रूप से अपने Docker मैपिंग (`/music`) को बनाए रखते हुए कॉन्फ़िगर किए गए होस्ट पथ (उदाहरण के लिए, `F:\Torrent\Music`) प्रदर्शित करता है। मौजूदा डाउनलोड माउंट अपरिवर्तित हैं. अतिरिक्त होस्ट फ़ोल्डरों को पहले Docker बाइंड माउंट के रूप में साझा किया जाना चाहिए; अनमाउंट किए गए फ़ोल्डर को चुनने पर एक त्रुटि दिखाई देती है और वर्तमान सेटिंग अपरिवर्तित रह जाती है।

- वही सेटिंग्स कार्ड अगला रन, संग्रहीत स्नैपशॉट गिनती, अंतिम सफल फ़ाइल और गिनती और सबसे हालिया विफलता दिखाता है। बैक अप नाउ एक सुरक्षित ऑन-डिमांड रन कतार में है; नवीनतम डाउनलोड करें नवीनतम निरंतर स्नैपशॉट पुनर्प्राप्त करता है।
- प्लेलिस्ट पृष्ठ पर, उस सेवा से प्रत्येक प्लेलिस्ट को एक संस्करण JSON या XML फ़ाइल में डाउनलोड करने के लिए सर्विस कार्ड पर निर्यात का उपयोग करें।
- केवल उस प्लेलिस्ट को निर्यात करने के लिए एक प्लेलिस्ट खोलें। इसका Soundiiz विकल्प [Soundiiz का दस्तावेजीकरण JSON आयात आकार](https://soundiiz.com/data/fileExamples/playlistExport.json) का अनुसरण करता है, इसलिए डाउनलोड की गई ट्रैक सूची Soundiiz की आयात प्लेलिस्ट → फ़ाइल प्रवाह से अपलोड की जा सकती है।
- SongMirror JSON/XML प्लेलिस्ट ऑर्डर और नाम प्लस प्रदाता ट्रैक/घटना आईडी, उपलब्ध आईएसआरसी, कलाकार, एल्बम, एल्बम ट्रैक स्थिति, अवधि, जोड़ी गई तिथियां, आर्टवर्क लिंक और अनुपलब्ध-प्रविष्टि मार्करों को संरक्षित करता है। आईडी-रहित कैटलॉग भूत गायब होने के बजाय बैकअप में बने रहते हैं। फ़ाइलों में कोई कुकीज़, टोकन, अनुरोध हेडर, पूर्वावलोकन या स्ट्रीमिंग-फ़ाइल यूआरएल नहीं हैं।

मैन्युअल निर्यात ब्राउज़र द्वारा यूआई चलाने वाले डिवाइस पर डाउनलोड किए जाते हैं। शेड्यूल किए गए निर्यात मौजूदा एप्लिकेशन-डेटा वॉल्यूम का उपयोग करते हैं, इसलिए किसी दूसरे होस्ट पथ या कंटेनर माउंट की आवश्यकता नहीं है। बैकअप प्रदाता क्लाइंट तक एक साथ पहुंचने के बजाय सिंक और ट्रांसफर के पीछे कतार को पढ़ता है। `schema_version` फ़ील्ड भविष्य के रिलीज़ को पुराने स्नैपशॉट को अस्पष्ट किए बिना दोषरहित प्रारूप विकसित करने देता है।

<a id="built-in-folder-picker"></a>

### अंतर्निहित फ़ोल्डर पिकर

अंतर्निहित पिकर खोलने के लिए फ़ोल्डर फ़ील्ड या ब्राउज़ करें... पर क्लिक करें। नेविगेट करने के लिए स्थान, क्लिक करने योग्य ब्रेडक्रंब, पीछे, आगे और एक फ़ोल्डर ऊपर का उपयोग करें। किसी फ़ोल्डर को चुनने के लिए उस पर क्लिक करें; इसे खोलने के लिए डबल-क्लिक करें, Enter दबाएँ, या इसके तीर का उपयोग करें। खोज वर्तमान फ़ोल्डर को फ़िल्टर करती है. एक फ़ोल्डर पथ दर्ज करें जो पूरा पता स्वीकार करता है। फ़ोल्डर का चयन करें ड्राफ्ट अपडेट करता है; इसे लागू करने के लिए सेटिंग्स सहेजें या शेड्यूल करें। रद्द करने से ड्राफ्ट अपरिवर्तित रह जाता है। किसी डेस्कटॉप सहायक या अतिरिक्त प्रक्रिया की आवश्यकता नहीं है.

नया फ़ोल्डर वर्तमान में खुले स्थान पर एक नामित सबफ़ोल्डर बनाता है, फिर उसे खोलता है। मौजूदा वस्तुओं को कभी भी अधिलेखित नहीं किया जाता है। नाम प्रविष्टि रद्द करने से कुछ नहीं बनता; निर्माण के बाद पिकर को रद्द करने से डिस्क पर नया फ़ोल्डर निकल जाता है। चयन करने और सहेजने के बाद ही आपका सहेजा गया बैकअप या डाउनलोड स्थान बदलता है। Docker में, पिकर बताता है कि कौन से पथ साझा किए गए हैं और उपलब्ध होने पर कंटेनर पथ और उसके कॉन्फ़िगर किए गए कंप्यूटर पथ दोनों को दिखाता है।

<a id="local-download-mirror-jellyfin"></a>

## 💿स्थानीय डाउनलोड मिरर (Jellyfin)

प्रत्येक सिंक की गई प्लेलिस्ट की एक ऑफ़लाइन ऑडियो कॉपी, प्रति प्लेलिस्ट एक फ़ोल्डर, [spotDL](https://github.com/spotDL/spotify-downloader) के माध्यम से रखें। सिंक ट्रू मिररिंग है: नए ट्रैक डाउनलोड किए जाते हैं, हटाए गए ट्रैक स्थानीय रूप से हटा दिए जाते हैं। लेआउट Jellyfin-तैयार है - डाउनलोड निर्देशिका पर Jellyfin संगीत लाइब्रेरी को इंगित करें और ट्रैक और प्लेलिस्ट दोनों दिखाई देते हैं, हर बार अपडेट रहते हैं:

```text
<DOWNLOAD_DIR>/
  <Playlist>/
    <Playlist>.m3u8          # auto-(re)generated; Jellyfin imports it as a playlist
    cover.jpg                # the source playlist cover, highest resolution
    <AlbumArtist>/
      <Album>/
        Artists - Title.mp3  # tagged + cover art embedded
```

`DOWNLOAD_DIR` सेट करके और spotDL + ffmpeg इंस्टॉल करके इसे सक्षम करें:

```bash
uv tool install spotdl       # isolated CLI; or: pipx install spotdl
# ffmpeg required: winget install ffmpeg   (or: spotdl --download-ffmpeg)
```

- वृद्धिशील - पहले पूर्ण डाउनलोड के बाद, केवल नए जोड़े गए ट्रैक लाए जाते हैं; हटाए गए ट्रैक (और उनके खाली एल्बम फ़ोल्डर) को काट दिया जाता है। एक बाधित रन अगले पास जारी रहता है।
- नवीनतम-प्रथम `.m3u8` - दिनांक-जोड़े गए क्रम में लिखा गया है, शीर्ष पर नवीनतम (फ़्लिप करने के लिए `LOCAL_MIRROR_ORDER=oldest` सेट करें)। `uv run main.py --refresh-local` के साथ मौजूदा फ़ाइलों से कवर/टैग/एमटाइम्स का पुनर्निर्माण करें।
- प्लेलिस्ट Jellyfin में शामिल है - Jellyfin एक m3u के बगल में एक कवर फ़ाइल को अनदेखा करता है, इसलिए `JELLYFIN_URL` + `JELLYFIN_API_KEY` सेट करें और प्रत्येक पास Jellyfin API के माध्यम से वास्तविक प्लेलिस्ट कवर अपलोड करता है।
- ऑडियो गुणवत्ता - स्रोत YouTube है, इसलिए YT Music Premium कुकी के बिना अधिकतम सीमा ~128–160 kbps है। `LOCAL_MIRROR_FORMAT=opus` YouTube की मूल स्ट्रीम को एमपी3 री-एन्कोड के बिना रखता है; एक Premium कुकी (`LOCAL_MIRROR_COOKIE_FILE`) 256 केबीपीएस एएसी को अनलॉक करती है। `flac` का चयन करने से आउटपुट कंटेनर बदल जाता है लेकिन हानिपूर्ण स्रोत को दोषरहित ऑडियो में नहीं बदला जा सकता है।

Monochrome का वर्तमान FLAC पथ एक स्थिर, प्रदाता-अधिकृत फ़ाइल-निर्यात API के बजाय ब्राउज़र-गेटेड, एकल-उपयोग प्लेबैक संसाधनों का उपयोग करता है, इसलिए SongMirror इसे स्वचालित नहीं करता है। स्थानीय दर्पण का उपयोग केवल उस सामग्री के लिए करें जो आपके स्वामित्व में है या अन्यथा प्रतिलिपि बनाने के लिए अधिकृत हैं।

## 🔌प्रत्येक सेवा को जोड़ना

वेब ऐप में, अकाउंट पेज आपको प्रत्येक सेवा के बारे में बताता है और चिपकाने के लिए सटीक मान दिखाता है। किसी तीसरे पक्ष के माध्यम से कुछ भी प्रॉक्सी नहीं किया जाता है।

<a id="credential-renewal"></a>

### क्रेडेंशियल नवीनीकरण

SongMirror समय पर क्रेडेंशियल ताज़ा करता है, अलग टोकन-रीफ्रेश टाइमर के साथ नहीं। प्रत्येक मैनुअल या शेड्यूल्ड सिंक पास अपने द्वारा उपयोग किए जाने वाले कनेक्टर्स को मान्य करता है और पहले अनुरोध से पहले (या एक बार प्रमाणीकरण अस्वीकृति के बाद) समर्थित एक्सेस टोकन को नवीनीकृत करता है। अल्पकालिक एक्सेस टोकन का पास के बीच समाप्त होना सामान्य बात है - टिकाऊ ताज़ा टोकन या नवीनीकरण कुकी ही मायने रखती है। अकाउंट पेज लोड होने या फोकस पुनः प्राप्त होने पर स्थिति को मान्य करता है, लेकिन यह पृष्ठभूमि सत्र रखरखाव नहीं है; सक्षम सिंक शेड्यूल हैं।

| Deezer | अल्पकालिक पाइप JWT उपयोग से पहले और एक बार `401/403` के बाद सहेजे गए `refresh-token` से स्वचालित रूप से नवीनीकृत हो जाता है; घुमाया हुआ नवीनीकरण स्थिति कायम है। |

| Jellyfin | API कुंजी में कोई एक्सेस-टोकन ताज़ा चक्र नहीं है; इसे तभी बदलें जब इसे निरस्त कर दिया गया हो या हटा दिया गया हो। |

<a id="spotify"></a>

### Spotify

1. <https://open.spotify.com> पर साइन इन करें।
2. ब्राउज़र खोलें DevTools (`F12`) → एप्लिकेशन (Chrome/Edge) या स्टोरेज (Firefox) → कुकीज़ → `https://open.spotify.com`.
3. `sp_dc` कुकी का मान कॉपी करें और इसे अकाउंट → Spotify में पेस्ट करें।

वह एकल साइन-इन वेब सत्र लाइब्रेरी ब्राउज़िंग, प्लेलिस्ट पढ़ने और लिखने और कैटलॉग खोज को संभालता है। इसके लिए Spotify डेवलपर ऐप, API कुंजी, या Premium खाते की आवश्यकता नहीं है। `sp_dc` को पासवर्ड की तरह समझें: SongMirror इसे अपनी निजी डेटा निर्देशिका में संग्रहीत करता है, लेकिन एकीकरण Spotify के आंतरिक वेब-प्लेयर संचालन का उपयोग करता है और यदि Spotify उन्हें बदलता है तो रखरखाव की आवश्यकता हो सकती है। मौजूदा डेवलपर-ऐप OAuth क्रेडेंशियल एक संगत फ़ॉलबैक बने हुए हैं।

<a id="tidal"></a>

### TIDAL

1. [TIDAL का वेब प्लेयर](https://listen.tidal.com) खोलें, DevTools → नेटवर्क खोलें, और संरक्षित लॉग सक्षम करें।
2. साइन आउट करें और वापस साइन इन करें, फिर `oauth2/token` के लिए नेटवर्क सूची फ़िल्टर करें।
3. सफल `auth.tidal.com/v1/oauth2/token` अनुरोध का चयन करें। पेलोड (Chrome/Edge) या अनुरोध (Firefox) में, `client_id` फॉर्म मान को SongMirror के वेब-प्लेयर क्लाइंट आईडी फ़ील्ड में कॉपी करें।
4. अनुरोध का रिस्पांस टैब खोलें और इसकी पूरी JSON को वेब-प्लेयर टोकन रिस्पांस में कॉपी करें। इसमें `access_token` और `refresh_token` दोनों शामिल होने चाहिए।
5. कनेक्ट करें. SongMirror तुरंत ताज़ा अनुदान का उपयोग करता है और यदि वह क्लाइंट आईडी इसे नवीनीकृत नहीं कर सकता है तो सफलता की रिपोर्ट करने से इंकार कर देता है।

OAuth क्लाइंट आईडी अनुरोध मेटाडेटा है और TIDAL के एक्सेस टोकन के अंदर संख्यात्मक `cid` दावा नहीं है। SongMirror केवल एक्सेस टोकन, रिफ्रेश टोकन, क्लाइंट आईडी, स्कोप, समाप्ति और कैटलॉग देश निकालता है; असंबद्ध प्रतिक्रिया डेटा को छोड़ दिया जाता है। यह समाप्ति से ठीक पहले और एक बार प्रमाणीकरण अस्वीकृति के बाद `https://auth.tidal.com/v1/oauth2/token` के माध्यम से नवीनीकृत होता है, ताज़ा-टोकन रोटेशन को संरक्षित करता है। पुराना OpenAPI अनुरोध-हेडर पेस्ट संगत रहता है, लेकिन क्योंकि इसमें कोई ताज़ा टोकन नहीं है, इसे समाप्ति के बाद भी इसे फिर से चिपकाने की आवश्यकता होती है। केवल कैटलॉग मेटाडेटा और साइन-इन किए गए उपयोगकर्ता की प्लेलिस्ट का उपयोग किया जाता है - प्लेबैक संपत्तियां इस एकीकरण से बाहर रहती हैं।

<a id="qobuz"></a>

### Qobuz

<https://play.qobuz.com> पर साइन इन करें, DevTools → नेटवर्क खोलें, और `api.json/0.2` के लिए फ़िल्टर करें। `X-App-Id` और `X-User-Auth-Token` वाले किसी भी अनुरोध को चुनें - जिसमें एक प्रमाणित `album/story` अनुरोध भी शामिल है - फिर उसके अनुरोध हेडर को कॉपी करें या इसे cURL के रूप में कॉपी करें और विज़ार्ड में पेस्ट करें। SongMirror केवल उन दो मानों को कायम रखता है, उन्हें वेब प्लेयर के समान हेडर-आधारित प्रवाह का उपयोग करके भेजता है, और कुकीज़ और असंबंधित ब्राउज़र मेटाडेटा को हटा देता है। किसी व्यवसाय API अनुमोदन या उपयोगकर्ता आईडी की आवश्यकता नहीं है; मौजूदा भागीदार क्रेडेंशियल एक संगत वातावरण फ़ॉलबैक बने हुए हैं।

एडॉप्टर केवल कैटलॉग खोज और प्लेलिस्ट एंडपॉइंट का उपयोग करता है - यह स्ट्रीम या फ़ाइल यूआरएल का अनुरोध नहीं करता है।

<a id="deezer"></a>

### Deezer

<https://www.deezer.com> पर साइन इन करें, DevTools → नेटवर्क खोलें, और पृष्ठ को पुनः लोड करें। `auth.deezer.com/login/renew` के लिए फ़िल्टर करें, उस अनुरोध के हेडर को कॉपी करें (या इसे cURL के रूप में कॉपी करें), और इसे नवीनीकरण फ़ील्ड में पेस्ट करें। Firefox इसके बजाय अनुरोध कुकीज़ को नंगे अर्धविराम-सीमांकित ब्लॉक के रूप में कॉपी कर सकता है; वह आकृति भी स्वीकृत है. SongMirror केवल समर्पित `refresh-token` कुकी को बरकरार रखता है और इसका उपयोग Deezer के अल्पकालिक पाइप JWT को स्वचालित रूप से नवीनीकृत करने के लिए करता है। आप मौजूदा `pipe.deezer.com/api` अनुरोध को तत्काल बूटस्ट्रैप के रूप में भी पेस्ट कर सकते हैं, लेकिन नवीनीकरण कॉन्फ़िगर होने पर इसकी आवश्यकता नहीं है। प्लेलिस्ट जोड़ना और हटाना दोनों ही नवीकरणीय पाइप सत्र का उपयोग करते हैं; नहीं `arl` कुकी की आवश्यकता है। मौजूदा डेवलपर OAuth टोकन एक संगत वातावरण फ़ॉलबैक बने हुए हैं।

<a id="amazon-music"></a>

### Amazon Music

डिफ़ॉल्ट कनेक्टर के लिए किसी डेवलपर अनुमोदन की आवश्यकता नहीं है। यह Amazon Music वेब प्लेयर के समान प्रमाणित GraphQL और टोकन-नवीनीकरण मार्गों का उपयोग करता है:

1. <https://music.amazon.com> पर साइन इन करें और DevTools → नेटवर्क खोलें।
2. पृष्ठ को पुनः लोड करें, `config.json` के लिए फ़िल्टर करें, और साइन-इन अनुरोध का चयन करें। (`pandaToken` प्रकट होने पर भी काम करता है, लेकिन इसकी आवश्यकता नहीं है।)
3. अनुरोध हेडर कॉपी करें या cURL के रूप में कॉपी करें चुनें, फिर इसे नवीनीकरण फ़ील्ड में पेस्ट करें। संपूर्ण `User-Agent`, `Referer`, और `Cookie` हेडर रखें ताकि SongMirror उसी ब्राउज़र संदर्भ को दोबारा चला सके।
4. वैकल्पिक रूप से साइन-इन `config.json` प्रतिक्रिया को बूटस्ट्रैप फ़ील्ड में कॉपी करें; SongMirror सामान्य रूप से नवीनीकरण सत्र का उपयोग करके उस डिवाइस संदर्भ को प्राप्त कर सकता है।

SongMirror स्थानीय स्तर पर समान `AmznMusic` प्राधिकरण मूल्य प्राप्त करता है और समाप्ति से पहले या प्रमाणीकरण अस्वीकृति के बाद एक बार `music.amazon.com/pandaToken` के माध्यम से इसे ताज़ा करता है। कनेक्शन के दौरान यह डिवाइस संदर्भ की आवश्यकता होने पर वर्तमान ब्राउज़र-शैली कॉन्फ़िगरेशन अनुरोध का उपयोग करता है, एक्सेस टोकन को मिंट करने के लिए `/pandaToken` की आवश्यकता होती है, और यदि अमेज़ॅन संगीत नवीनीकरण कुकी को रद्द कर देता है तो कनेक्शन को अस्वीकार कर देता है। यह केवल ब्राउज़र उपयोगकर्ता एजेंट, भाषा, संगीत रेफरर, अमेज़ॅन प्रमाणीकरण/सत्र कुकीज़ की नामित अनुमति सूची और सीमित संगीत-क्लाइंट डिवाइस संदर्भ संग्रहीत करता है; एनालिटिक्स, प्रयोग, एडब्ल्यूएस-कंसोल, सीएसआरएफ और अन्य असंबंधित ब्राउज़र डेटा को छोड़ दिया जाता है। वे रखी गई कुकीज़ अभी भी संवेदनशील हैं, इसलिए अपने LAN पर SongMirror को निजी रखें। लॉगआउट, पासवर्ड/सुरक्षा परिवर्तन, या अमेज़ॅन-साइड निरस्तीकरण के लिए अभी भी एक नए कैप्चर की आवश्यकता हो सकती है।

यह एक असमर्थित प्रथम-पक्ष वेब-क्लाइंट इंटरफ़ेस है और अमेज़ॅन इसे बिना किसी सूचना के बदल सकता है। प्रलेखित [Amazon Music वेब API](https://developer.amazon.com/docs/music/API_web_overview.html) अभी भी एक बंद बीटा है; पर्यावरण चर के माध्यम से कॉन्फ़िगर किए जाने पर स्वीकृत भागीदार क्रेडेंशियल एक वैकल्पिक फ़ॉलबैक बने रहते हैं।

<a id="apple-music"></a>

### Apple Music

किसी Apple डेवलपर खाते की आवश्यकता नहीं है - `music.apple.com` से दो हेडर पर्याप्त हैं। <https://music.apple.com> खोलें, साइन इन करें, DevTools → नेटवर्क खोलें, एक गाना चलाएं, `amp-api.music.apple.com` के लिए फ़िल्टर करें, और किसी भी अनुरोध के हेडर से कॉपी करें:

- `authorization: Bearer eyJ...` → Bearer टोकन (`eyJ...` भाग, `Bearer ` के बिना)
- `media-user-token: ...` → उपयोगकर्ता टोकन (पूर्ण मूल्य)

कनेक्ट विज़ार्ड आपको कच्चे हेडर को पेस्ट करने और आपके लिए मानों को पार्स करने की सुविधा देता है। पिछले महीनों के टोकन; उनकी समय सीमा समाप्त होने पर उन्हें लेखा पृष्ठ पर पुनः चिपकाएँ।

सक्रिय Apple Music सदस्यता के बिना एक Apple ID अभी भी कैटलॉग-केवल मोड में कनेक्ट हो सकता है। उस मोड में, किसी अन्य कनेक्टेड सेवा में कॉपी करने के लिए ट्रांसफ़र पर एक सार्वजनिक Apple Music प्लेलिस्ट लिंक पेस्ट करें। Apple लाइब्रेरी ब्राउजिंग, शेड्यूल्ड सिंकिंग और ट्रांसफर डेस्टिनेशन के रूप में Apple Music का उपयोग करने के लिए अभी भी भुगतान किए गए CloudLibrary विशेषाधिकार की आवश्यकता होती है; SongMirror वैध कैटलॉग क्रेडेंशियल को समाप्त मानने के बजाय उन परिचालनों को अनुपलब्ध दिखाता है।

<a id="youtube-music"></a>

### YouTube Music

अधिकारी [YouTube Data API v3](https://developers.google.com/youtube/v3) से बात करता है, जिसका OAuth ताज़ा टोकन टिकाऊ है और पुनरारंभ होने से बच जाता है।

1. [Google क्लाउड कंसोल](https://console.cloud.google.com) में, एक प्रोजेक्ट बनाएं, YouTube Data API v3 सक्षम करें, और टीवी और सीमित इनपुट डिवाइस प्रकार का OAuth क्लाइंट बनाएं।
2. OAuth सहमति स्क्रीन पर, प्रकाशन स्थिति → उत्पादन में सेट करें (इसे "परीक्षण" में छोड़ने से 7 दिनों के बाद टोकन समाप्त हो जाता है)।
3. ऐप में क्लाइंट आईडी + सीक्रेट पेस्ट करें और ऑन-स्क्रीन डिवाइस कोड पूरा करें।

> कोटा: Data API 10,000 यूनिट/दिन की अनुमति देता है (एक खोज की लागत 100, जोड़ने/निकालने की लागत 50 है)। स्थिर-अवस्था रखरखाव सस्ता है; पहली बार का बड़ा बैकलॉग अधिकतम सीमा तक पहुँच सकता है और अगले दिन फिर से शुरू हो सकता है।

<a id="headless-cli"></a>

## 🖥️ ग्राफिकल इंटरफ़ेस सीएलआई के बिना

`.env` + cron / Task Scheduler को प्राथमिकता दें? वही इंजन बिना ग्राफ़िकल इंटरफ़ेस के चलता है।

```bash
uv sync
cp .env.example .env            # fill in credentials
uv run main.py                  # dry run — prints every add/remove it *would* do
uv run main.py --execute        # apply for real
```

उपयोगी झंडे:

```bash
uv run main.py --execute --playlists "Aurora,Chill"   # only these pairs
uv run main.py --execute --loop --interval 15m        # run forever
uv run main.py --execute --max-removals 100           # one-off larger cleanup
uv run main.py --execute --sync-mode group --sync-source spotify \
  --authorities spotify,apple --providers spotify,apple,tidal,ytmusic
```

मुख्य पर्यावरण संस्करण (देखें `.env.example`): आप जिस भी प्रदाता का उपयोग करते हैं उसके लिए क्रेडेंशियल, `PLAYLISTS`, `SYNC_INTERVAL`, `MAX_ADDS` / `MAX_REMOVALS`, `DOWNLOAD_DIR`, `SYNC_MODE`, `SYNC_SOURCE`, `SYNC_AUTHORITIES`, और `PROVIDERS`.

## 🛡️ सुरक्षा उपाय

निष्कासन विनाशकारी हैं, इसलिए उनकी सुरक्षा की जाती है:

- सिमुलेशन डिफ़ॉल्ट है - `--execute` (या यूआई की वास्तविक-सिंक कार्रवाई) के बिना कुछ भी नहीं बदलता है।
- यदि स्रोत प्लेलिस्ट के लिए 0 ट्रैक लौटाता है, तो लक्ष्य गैर-रिक्त के रूप में दिखाता है, उस पास को हटा दिया जाता है (एक क्षणिक API विफलता किसी प्लेलिस्ट को खाली नहीं कर सकती)।
- **गाने हटाना डिफ़ॉल्ट रूप से बंद है** — `MAX_REMOVALS=0` हर हटाने की कार्रवाई रोकता है; उसे लॉग किया जाता है, लागू नहीं किया जाता। इसलिए एक प्लेटफ़ॉर्म पर लाइसेंस के कारण गाना हटने से वह बाकी प्लेटफ़ॉर्म पर अपने आप नहीं मिटता। हर सिंक के लिए **गानों का हटना सिंक करें** चालू करें या `MAX_REMOVALS` सेट करें। चालू होने के बाद भी, अगर एक बार चलने के दौरान हटाए जाने वाले गानों की संख्या सीमा से अधिक हो, तो सभी हटाने की कार्रवाइयाँ छोड़ दी जाती हैं और लॉग की जाती हैं।
- `MAX_ADDS` कालक्रम मरम्मत सहित सिंक पास में प्रत्येक टाइमस्टैम्प-उत्पादक लेखन को सीमित करता है। यदि किसी पुराने पुनर्प्राप्त मैच को कैप की अनुमति से अधिक बड़े प्रत्यय रीप्ले की आवश्यकता होती है, तो SongMirror इसे नवीनतम दिखाने या एक विशाल प्रदाता विस्फोट का कारण बनने के बजाय इसे अगले पास के लिए स्थगित कर देता है। एक बार के स्थानांतरण में कोई अगला पास नहीं होता है, इसलिए यह कभी भी स्थगित नहीं होता है: यह प्रत्येक अनुरोधित ट्रैक की प्रतिलिपि बनाता है, स्रोत क्रम में जोड़ता है जब तक कि आप उस स्थानांतरण के लिए "हाल ही में जोड़े गए ऑर्डर को संरक्षित करें" पर स्विच नहीं करते हैं, जो मरम्मत की लागत जो भी खर्च करता है।
- कालानुक्रमिक मरम्मत मूल को हटाने से पहले एक डुप्लिकेट प्रतिलिपि तैयार करती है। एक ऐसी सेवा पर जिसका डिलीट गीत की प्रत्येक प्रति लेता है, उस कीपर की गिनती सही होनी चाहिए, इसलिए Apple Music तब तक फिर से पढ़ता है जब तक कि चरणबद्ध प्रतियां दिखाई न दें और उस पठन के विरुद्ध कुछ भी रिटायर करने से इंकार कर देता है जो अभी भी अपने स्वयं के लेखन को पीछे छोड़ देता है। Deezer मरम्मत को पूरी तरह से छोड़ देता है और हमेशा संलग्न रहता है: इसमें कोई स्थितिगत सम्मिलन भी नहीं है, इसलिए जिस आदेश को यह व्यक्त नहीं कर सकता उसे दोबारा चलाना गंतव्य के लिए जोखिम के लायक नहीं है। स्थानांतरण प्रपत्र वहां अपना ऑर्डर स्विच धूसर कर देता है और बताता है कि क्यों।
- नेट-लॉस सुरक्षा - एक लक्ष्य-साइड ट्रैक जो स्रोत ट्रैक जैसा दिखता है, जिसका उस सेवा से कोई मेल नहीं है, को रोका जाता है, हटाया नहीं जाता है।
- कोई भी प्रदाता प्रमाणीकरण विफलता उस प्रदाता के पास को तुरंत निरस्त कर देती है - समाप्त हो चुके टोकन पर कोई आंशिक विलोपन नहीं होता है।
- मर्ज कार्य को अपने गंतव्य से हटाने से पहले पढ़े गए प्रत्येक घटक स्रोत को पूरा करना होगा; कोई भी आंशिक/विफल स्रोत स्नैपशॉट बल जो केवल-संलग्न व्यवहार में बदल जाता है।

## 🗃️ कैशिंग और गीत संग्रह

समाधान योग्य सभी चीजें कैश्ड हैं इसलिए स्थिर-स्थिति पास लगभग-तत्काल हैं: प्रति-सेवा रिज़ॉल्यूशन कैश (ISRC + खोज, चूक सहित), एक `snapshot_id`-कुंजी ट्रैक-सूची कैश, SQLite में सटीक पहचानकर्ता लिंक, और एक प्रति-जोड़ी स्नैपशॉट-स्किप (`unchanged since last clean sync`)।

प्रत्येक पास प्रत्येक ट्रैक के मेटाडेटा को `song_cache.db` में संग्रहीत करता है - एक SQLite फ़ाइल जो केवल बढ़ती रहती है। हटाए गए ट्रैक नाम, कलाकार, एल्बम, अवधि, ISRC, कच्चे स्नैपशॉट JSON, और पहली/अंतिम बार देखे गए टाइमस्टैम्प के साथ संग्रहीत रहते हैं:

```bash
sqlite3 song_cache.db "SELECT name, artist, album, first_seen FROM songs ORDER BY first_seen DESC LIMIT 20"
```

<a id="resolve-mappings"></a>

### मैपिंग का समाधान करें

प्रत्येक सेवा अपना स्वयं का रिज़ॉल्यूशन कैश रखती है, एक सामान्यीकृत `title|artist` कुंजी को उस कैटलॉग आईडी पर मैप करती है जिस पर वह मेल खाती है
वह सेवा. एक मैच का हमेशा के लिए पुन: उपयोग किया जाता है, और इसी तरह "नो मैच" परिणाम भी होता है, जो एक ट्रैक को विफल बनाता है
एक बार मैच करने के लिए बाद के हर पास पर बेजोड़ बने रहना।

वेब यूआई में मैपिंग पेज प्रति सेवा सीधे उन कैश को उजागर करता है:

- संपूर्ण कैश को शीर्षक, कलाकार या हल की गई आईडी के आधार पर खोजें
- हाथ से सेट की गई प्रविष्टियों को फ़िल्टर करें (एक मिलान जिसे आपने स्थानांतरण विरोध संपादक में चुना है) या बिना मिलान वाली प्रविष्टियों को फ़िल्टर करें
- सही ट्रैक का लिंक चिपकाकर गलत आईडी को ठीक करें, या मैपिंग हटा दें ताकि अगला पास उसे फिर से देख सके
- किसी सेवा के लिए प्रत्येक "कोई मिलान नहीं" प्रविष्टि को एक कार्रवाई में साफ़ करें, ताकि विफल लुकअप के एक बैच को एक और प्रयास मिल सके

जब कोई चूक बाद में ठीक हो जाती है, तो उसे जोड़ने मात्र से पुराना गाना नवीनतम दिखाई देने लगेगा। प्लेलिस्ट के लिए
गंतव्य, SongMirror इसके बजाय उस गीत को दोबारा चलाता है और पहले से मौजूद नए प्रत्यय को सबसे पुराने से नवीनतम तक हटा देता है, फिर हटा देता है
पुरानी प्रतियाँ. प्रदाता ग्राहकों को मूल टाइमस्टैम्प को पुनर्स्थापित करने की अनुमति नहीं देते हैं, लेकिन यह उनके रिश्तेदार को सुरक्षित रखता है
हाल ही में जोड़ा गया ऑर्डर. मूल पसंदीदा/पसंदीदा संग्रह केवल सदस्यता के लिए ही बने रहते हैं और इन्हें कभी भी दोबारा नहीं चलाया जाता है।

जब सिंक चल रहा हो तो संपादन को स्पष्ट संदेश के साथ अस्वीकार कर दिया जाता है, क्योंकि पास इसके लिए मेमोरी में कैश रखता है
पूरी अवधि और पूरा होने पर उन्हें अधिलेखित कर दिया जाएगा।

<a id="project-layout"></a>

## 🧱प्रोजेक्ट लेआउट

सीएलआई प्रविष्टि: `uv run main.py` (पतला शिम) या `python -m songmirror`। वेब प्रविष्टि: `songmirror.web:app`.

```text
songmirror/
  engine/       # provider-agnostic sync core (no web deps): runner, matching, targets/, spotify, downloads, archive
  services/     # stateful services over the engine: accounts/ connectors, syncs, sync_service, transfers, playlists, settings
  web/          # FastAPI app: thin HTTP/SSE over services/ (routers/)
frontend/       # React + Vite SPA (built and served by the API in production)
```

एक और सेवा जोड़ना: उपवर्ग `MirrorTarget`, ~8 तरीकों को लागू करें, इसके बिल्डर को `engine/targets`' `_REGISTRY` और इसके वर्ग को `_CLASSES` में जोड़ें, और `services/accounts` के अंतर्गत एक मिलान `Connector` जोड़ें। सभी सामंजस्य - अंतर, ऑर्डरिंग, सुरक्षा सुरक्षा उपाय, लॉगिंग, स्नैपशॉट-स्किप - विरासत में मिला है।

<a id="troubleshooting"></a>

## 🩺समस्या निवारण

- `Missing required environment variable` — `.env` (सीएलआई) भरें या यूआई में सेवा कनेक्ट करें।
- TIDAL रिपोर्ट `Expired` - साइन आउट करें और `listen.tidal.com` पर वापस जाएं, फिर `oauth2/token` अनुरोध पेलोड से `client_id` और इसकी पूरी प्रतिक्रिया JSON दोनों को अकाउंट्स में पेस्ट करें। कॉपी किए गए OpenAPI अनुरोध में केवल अल्पकालिक Bearer है और इसे नवीनीकृत नहीं किया जा सकता है।
- TIDAL रिपोर्ट HTTP 429 — यह एक अस्थायी दर सीमा है, कोई समाप्त साइन-इन नहीं। SongMirror प्रदाता को पुनः प्रयास में देरी का सम्मान करता है और API की बार-बार जांच करने के बजाय कैश खाते की स्वास्थ्य जांच करता है।
- Qobuz या Apple रिपोर्ट `Expired` / `401` / `403` — इन चिपकाए गए सत्रों में कोई नवीकरणीय रहस्य नहीं है; खातों में एक ताज़ा साइन-इन अनुरोध या टोकन प्राप्त करें।
- TIDAL का कहना है कि टोकन में लाइक-ट्रैक एक्सेस का अभाव है - `r_usr` और `w_usr` वाले एक नए साइन-इन वेब-प्लेयर टोकन प्रतिक्रिया को कैप्चर करें।
- Deezer नवीनीकरण विफल रहता है - एक ताज़ा `auth.deezer.com/login/renew` अनुरोध (या इसकी `refresh-token` कुकी) कैप्चर करें। एक वर्तमान पाइप Bearer अकेले एक अस्थायी बूटस्ट्रैप है।
- Amazon Music नवीनीकरण विफल रहता है - एक नए साइन-इन `POST /config.json?skipToken=false` अनुरोध को उसके पूर्ण `User-Agent`, `Referer`, और `Cookie` हेडर के साथ कैप्चर करें। प्रतिक्रिया JSON वैकल्पिक है।
- YouTube Music ब्राउज़र मोड समाप्त हो रहा है - ताज़ा ब्राउज़र अनुरोध हेडर निर्यात करें। सबसे टिकाऊ अप्राप्य सेटअप के लिए, इन-प्रोडक्शन सहमति स्क्रीन के साथ Data API OAuth का उपयोग करें।
- Spotify रिपोर्ट समाप्त हो गई है - `open.spotify.com` पर फिर से साइन इन करें और अकाउंट्स में एक ताज़ा `sp_dc` कुकी पेस्ट करें।
- एक प्लेलिस्ट सिंक नहीं हो रही है - पुष्टि करें कि यह सिंक के प्लेलिस्ट दायरे में है और स्रोत पर मौजूद है (लक्ष्य वास्तविक पास पर स्वतः निर्मित होते हैं)।
